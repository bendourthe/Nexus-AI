# v2.16.2 QG-1 Windows Sandbox Evidence

Owner decision D2 requires gates B3-B6 to pass against the application installed from the candidate's frozen Windows installer inside a disposable Windows Sandbox or VM, never on the maintainer's account. This file records that proof, the defect it found, and the fix. Machine-readable receipts: [v2.16.2-qg1-sandbox-receipts.json](v2.16.2-qg1-sandbox-receipts.json).

## Result

QG-1 passes on candidate `241da375a3310ff38e81d0ee12f070e82db6c0b7`. The first clean run, on the pre-fix candidate `acc4adff`, found BG-1: the installed app could not start on a PC without the Visual C++ Redistributable. Commit `241da375` fixes it, and the fixed installer passes every gate on a clean Sandbox.

## Method

- **Installer**: built by `installer-build.yml` on a GitHub-hosted runner, downloaded as the `NexusSetup-windows` artifact. Nothing was built or installed on the maintainer's account.
- **Boundary**: Windows Sandbox (`WDAGUtilityAccount`, Windows 11 Enterprise build 26100), discarded after each run. Mapped read-only: the guest script and installer, the candidate checkout, its shared `.git` folder and Git for Windows. Mapped writable: one output folder.
- **Guest script**: refuses unless it runs as `WDAGUtilityAccount` and every Nexus destination is absent. Installs with `NexusSetup.exe --headless-smoke` and the release smoke's profile (desktop component, no models). Runs the installed `--healthcheck`, then `desktop/tests/packaged/image-edit-flow.mjs` against the installed `nexus-shell.exe` with the provisioned Node runtime, in edit mode and with both defect controls. Each process has a bounded wait and is killed with its tree on timeout.

## Defect Found: BG-1

`nexus-shell.exe` imported `VCRUNTIME140.dll` and `VCRUNTIME140_1.dll`; the Sandbox has neither (`vcruntime140Present: false`). Commit `f223770d` (2026-10-08) moved npm `@tauri-apps/cli` to 2.12, which no longer sets `STATIC_VCRUNTIME` (it reads `build.windows.staticVCRuntime` instead), while `desktop/src-tauri/Cargo.lock` pins `tauri-build` 2.6.3, which reads only that variable. Releases v2.12.0 through v2.16.1 contain that commit. The developer host and hosted runners have the redistributable installed, so no earlier check could see the failure.

Fix in `241da375`:

- `desktop/src-tauri/build.rs` sets `STATIC_VCRUNTIME=true` for MSVC targets unless the variable is already set.
- `scripts/installer/build/smoke-windows-exe.ps1` gains an `installed-crt-linkage` stage in the hosted `-InstallDesktop` path that fails when the installed app imports any `vcruntime*.dll`. Its PE reader reports both runtime imports on a pre-fix build and none on `notepad.exe`; run 44918087312 passed it on the fixed build.
- Local checks: `cargo check` and `cargo clippy -- -D warnings` exit 0.

## Also Observed

Recorded as Observation 8 in the [v2.16 known gaps](../known-gaps.md); it is outside this plan's scope.
