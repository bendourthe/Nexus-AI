## Steps

1. Confirmed Windows Sandbox was enabled (maintainer rebooted at 21:44 on 2026-11-20).
2. Built the frozen installer from `develop` (`acc4adff`) with `installer-build.yml` run 44874261359; local builds stay off the maintainer's desktop because the console-window guard blocks them in this checkout.
3. Ran the installer and the packaged image-edit check inside Windows Sandbox. The installed app exited `0xC0000135`.
4. Found the cause: `nexus-shell.exe` imports `VCRUNTIME140.dll` and `VCRUNTIME140_1.dll`; Tauri CLI 2.12 (`f223770d`) stopped setting `STATIC_VCRUNTIME` while `tauri-build` 2.6.3 still needs it. A diagnostic Sandbox run with Microsoft's signed redistributable installed passed every gate, which isolated the runtime as the only blocker.
5. With the maintainer's approval, committed `241da375`: `build.rs` sets `STATIC_VCRUNTIME=true` for MSVC, and the hosted `-InstallDesktop` smoke fails on any `vcruntime*.dll` import.
6. Built the fixed installer (run 44918087312; its smoke passed the new stage) and reran the clean Sandbox. After mapping the shared `.git` so the check could read the candidate commit, QG-1 passed.
