## Model-Wide Gates

Evaluate E-1, E-2, and E-3 in order. The first non-PASS stops candidate inference and admission for both slots. Later gates are recorded `not run`, never inferred from earlier evidence.

| ID | Gate | Pass rule |
|---|---|---|
| E-1 | Availability | An official `ollama.com/library` tag names E4B and lists tools. Check within 2026-10-23 through 2026-11-06 inclusive. Before the deadline, absence is pending availability; if absent after the window, record HOLD with reopen condition "official Ollama tag published". |
| E-2 | License | The official card's license text is OpenMDW-1.1, or another license without a revenue cap or redistribution ban. Record the URL and applicable clause. Announcements and sibling-model licenses are insufficient. |
| E-3 | Codec | At least five captured agentic transcripts each recover the expected tool name and arguments through the path Nexus actually uses. Zero parse failures are allowed. |

For E-3, build requests using Nexus's real tool definitions and the exact JSON shape of [headlessOllamaClient.ts](../../../../../modules/coding/llm/headlessOllamaClient.ts), including `tools` when the client sends it. Replay that request JSON through a plain HTTP POST to Ollama and save each raw response byte for byte. Record both `message.tool_calls` and `message.content`, plus `ollama show --template`. Recovery must use either structured calls consumed by this Nexus binding or an existing `TOOL_FORMAT_NAMES` parser over content. A new parser is outside scope. A fixture test documents either recovered calls or the actual observed failure; its being green is not itself an E-3 PASS.

Any codec parse failure in any later candidate golden run makes E-3 FAIL retroactively, ends the trial for both slots, and invalidates candidate admission regardless of E-4 or E-5.

## Per-Slot Gates

Only slots whose model-wide gates all pass proceed. Each slot stops at its first non-PASS.

| ID | Gate | Pass rule |
|---|---|---|
| E-4 | Fit, CPU | Peak system RAM measured from Ollama `/api/ps` is at most 2 times the holder's measured peak, with GPU offload disabled. |
| E-4 | Fit, GPU fallback | At `num_ctx: 32768`, peak VRAM is at most the holder's 3 GB catalog budget, with no RAM spill. |
| E-5 | Non-inferiority | Three complete runs per arm per slot; candidate median passed-task count is at least holder minimum passed-task count, and candidate pooled p95 turn time is at most 1.25 times holder pooled p95. |

Use the runner's `peakMemory` definitions: resident bytes from `size`, VRAM bytes from `size_vram`, and RAM bytes from `max(0, size - size_vram)`. Preserve raw samples and units. A missing model entry, failed API read, or absence of usable samples is unmeasured, not zero. A sample with another model resident is discarded and repeated after unloading it.

For E-5, a completed run finishes the entire selected task set and retains each result, including failed tasks. Per-run completed-task success is the number with `passed: true`, rather than merely the number attempted. Crashed or interrupted runs remain incomplete and never count toward three. Pool `turns[].turnMs` across all tasks in all three complete runs for each arm and slot. Compute p95 by nearest rank: sort ascending and take one-based rank `ceil(0.95 * N)`. A missing or empty timing pool cannot pass. Preserve codec failure counts even in unsuccessful tasks. Record CPU tokens per second for both arms, the raw timing/token observations and their derivation; do not substitute first-chunk latency for turn time.

An arm with fewer than three complete runs, or a budget that ends before both arms complete, yields HOLD for that slot. Non-inferiority serves the existing license-policy commitment; the candidate need not win on quality, but it must satisfy both frozen comparisons.
