## Recommendation

The highest-value lesson in this set is not a model. It is PersonaPlex's argument that voice latency is the product, applied to the voice loop Nexus already ships. `runtimes/audio/engines.py:93-121` builds a new Kokoro `KPipeline` on every `speak` call, converts every sample through a pure-Python loop, and returns one WAV only after the whole reply is synthesized, even though Kokoro already yields per-segment audio. Measuring time-to-first-audio and streaming those segments is a local, low-risk change to existing code (V1, V2). Adopting PersonaPlex itself is a conditional future evaluation at the 24 GB tier only (V3), because it brings its own 7B language model and so would bypass Nexus's chat model, memory, tools and routing during a voice session.

DigUp is the strongest reference implementation of what v2.13's E1/E2 plan already intends. It contributes three measured, directly portable mechanisms: a reference-vector regression test that pins embedding output across runtime upgrades, a labeled query fixture with duplicate and trap files, and a ranking scorer it measured against the same Reciprocal Rank Fusion that `core/memory/HybridRetriever.ts:4-5` uses. These are proposed as v2.13 amendments (D1 to D3). Nothing in DigUp justifies indexing the user's whole home folder; the v2.13 E3 scoping rule stands.

AirLLM's idea is already implemented in Nexus twice: the disk-offload patient tier (`core/registry/patientTier.ts:1-17`) and diffusion layer streaming (`runtimes/diffusion/device.py:86-131`). Adopting AirLLM would add a PyTorch/transformers LLM runtime whose own repository publishes no throughput figures, for a job the patient tier already holds. mimic is not recommended: its generator sends captured request and response bodies to a cloud AI CLI, and its capture path depends on defeating TLS pinning in third-party apps.

Support tiers: existing Nexus implementations cited below are **internal-compatible** evidence from code inspection, with end-to-end behavior **not proven here**. V1, V2 and D1 to D3 are **candidate**. V3 is **future**. No source capability was executed.

## Source 1: AirLLM

AirLLM 4.0.0 (Apache-2.0) loads a Hugging Face checkpoint, splits it into per-layer safetensors on disk, then runs each forward pass by loading one layer, computing, and freeing it. A worker thread prefetches the next layer into pinned host memory (`air_llm/airllm/airllm_base.py:66-73`, `:185-192`, `:442-452`). MoE models stream only routed experts (`:778-868`). Optional 4/8-bit block-wise compression shrinks what is read from disk, and disables prefetching (`:187-189`).

| Dimension | AirLLM | Nexus | Disposition |
|---|---|---|---|
| Disk-streamed LLM inference | Core feature, Python/transformers | Present as the patient tier: `core/registry/patientTier.ts:1-17` routes a user-registered llama.cpp flash-MoE offload adapter, off by default, with a measured "~0.03 tok/s (~32 s/token laptop, ~19-21 s/token server)" warning (`:29-30`) | Already implemented, different runtime |
| Layer streaming for other models | Not applicable | `runtimes/diffusion/device.py:86-131` chooses GPU, model CPU offload or sequential offload; `core/config/diffusionBudget.ts:76-87` warns when disk speed would thrash | Already implemented for diffusion |
| Throughput disclosure | None. No tok/s or s/token figure in the README, setup, or Python sources (searched) | The acceptance bar requires measured tokens/sec (`docs/reference/model-acceptance.md:119`) | Nexus is stronger; AirLLM claims cannot pass the bar as published |
| Context | `max_seq_len=512` default (`airllm_base.py:84`) | Agentic sessions depend on large context; v2.12 is sizing tool output by remaining window | Mismatch with the Coding pillar |
| Disk cost | Splitting writes a second full copy unless `delete_original` (README "Configurations" and FAQ 1) | Model storage is managed by the registry | New disk-doubling burden |

The decode-speed problem is structural, not a tuning gap. For a dense model, every generated token must read every layer from disk once. A 70B model at 16-bit is about 140 GB per token; at a typical 3 to 7 GB/s NVMe read that is roughly 20 to 45 seconds per token before compute (an estimate, not a measurement). That agrees with the order of magnitude Nexus already measured for its own patient tier. It is usable for batch scoring or a one-off long answer, and unusable for an agent loop that issues many tool-calling turns.

**Adoptable idea, A1:** none as code. The one transferable observation is AirLLM's explicit trade between compression and prefetch; the patient tier already exposes RAM presets and timeouts. No AirLLM work is proposed.

## Source 2: DigUp

DigUp (MIT) is a macOS menu-bar app with a Windows/Linux Tauri shell in progress (`shell/src-tauri/`). It runs ggml-org's 8-bit EmbeddingGemma 2 through a pinned llama.cpp in a helper process, stores 768-dimensional vectors plus an FTS keyword index in one SQLite file, and indexes images, PDF pages, documents, 30-second overlapping audio windows and sampled video frames (README "What it reads" and "How it works").

This overlaps the v2.13 plan's E1 (text/code evaluation), E2 (embedding identity and migration) and E3 (media retrieval, deferred). The comparison below records only what DigUp adds beyond what v2.13 already says.

| DigUp mechanism | Evidence | Nexus today | v2.13 coverage | Delta |
|---|---|---|---|---|

Nexus embeds through Ollama, whose upgrades can change vectors silently | Not covered; E2 guards model and recipe changes, not same-model runtime drift | **D1, new** |
| Labeled query fixture with expected files, segment anchors (`file@0-6`), and deliberate traps (duplicates, renamed copies, mislabeled container formats) | `evals/synthetic.json`, `evals/code.json`, `evals/multilingual.json` | Phase 1 of v2.13 creates the labeled set | Requires at least 30 queries with paraphrases, hard negatives and no-answer cases | **D2**: adopt the trap categories and the JSON shape |

## Source 3: mimic

mimic (MIT) captures an app's HTTPS traffic through mitmproxy (or a HAR file or "Copy as cURL"), replays the captured auth headers, and asks an AI CLI to write a named-method Python client from the captured endpoints. Its README example drives a dating app's recommendation and "like" endpoints.

| Insight | Status | Evidence |
|---|---|---|
| Generate a typed client from a HAR file or cURL capture | Missing; not a product job | No HAR, mitmproxy or client-generation code in Nexus (inventory search). `STRATEGY.md`'s solo-builder persona does not name third-party app automation. |
| Generation through a cloud AI CLI | Conflicts with policy | `mimic/codegen.py:60-79` runs `claude -p --model sonnet` (or `opencode run`) with the prompt on stdin. `build_digest` (`:41-53`) includes full request and response bodies, which for the README's example are private messages and profiles. Auth headers are excluded (`extract.py:43-57`). |
| Capture of pinned apps | Conflicts with policy | `mimic/unpin.py:1-21` orchestrates Frida hooks that disable TLS verification, and IPA re-signing for stock devices. |

A local equivalent ("turn this HAR into a client") is achievable as an ordinary Coding pillar request with the user's own local model and no new code. It is not proposed as a feature because no Nexus user need was identified and the capture side is the hard, risky part.

## Source 4: PersonaPlex

PersonaPlex fine-tunes Kyutai's Moshi on Helium to listen and speak simultaneously, conditioned by a text role prompt and a voice embedding. Code is MIT; weights are under the NVIDIA Open Model License behind a gated Hugging Face download that requires an account and `HF_TOKEN` (README "Accept Model License" and "License"). Voice conditioning in the inspected server uses a fixed set of 18 pre-packaged embeddings (`NATF0` to `VARM4`) selected by filename; `load_voice_prompt` can also take raw audio (`moshi/moshi/models/lm.py:960-975`). Training data named in the README is synthetic plus the Fisher English corpus; non-English quality is not proven here.

| Dimension | PersonaPlex | Nexus | Disposition |
|---|---|---|---|
| Voice turn model | Full duplex, one model | Half duplex: VAD or push-to-talk capture, faster-whisper STT, chat model, Kokoro TTS; barge-in stops playback (`desktop/src/modules/chat/voiceLoop.ts:1-10`) | Different approach; Nexus keeps its own model, memory and tools in the loop |
| Latency | "Under 300 ms" claimed | Not measured. `runtimes/audio/engines.py:93-121` constructs `KPipeline(lang_code="a")` per call, joins all Kokoro segments, converts float to int16 in a Python loop (`:125-137`), and returns one base64 WAV | **V1, V2** |
| Persona control | Text role prompt plus voice embedding | Kokoro voice fixed to `af_heart` in `speak` | Recorded; voice choice is a small follow-up to V2, not proposed separately |
| Hardware | "Under 16 GB" claimed; `--cpu-offload` documented | Voice runs alongside the tier's chat model; 16 GB tier holds `gemma-4-12b-it-gguf` | Co-residency not proven; 24 GB tier only for any trial |
| Runtime | New Python runtime; `torch >=2.2,<2.5`, `libopus` | Three runtime jobs exist (`docs/reference/model-acceptance.md:89-91`) | A fourth runtime must claim a job on the map |
| Integration | Its own 7B LM answers | Chat pillar routes to the tier's model with memory and tools | Voice sessions would lose Nexus memory, tools and routing |

## Security assessment

**Threat model.** Nexus's runtime destinations are local; model provisioning fetches public weights, and inference stays on the host. This research contacted GitHub only. No project source, conversation or secret was sent anywhere.

| Source | New runtime dependencies | Outbound calls at use time | Credentials | Data leaving the machine | Commercial relationship |
|---|---|---|---|---|---|
| AirLLM | torch, transformers, accelerate, safetensors, huggingface-hub (`air_llm/setup.py`) | Hugging Face download on first load | HF token for gated models | None after download | None |
| DigUp patterns (D1 to D3) | None; tests and scorer reuse existing modules | None | None | None | None |
| mimic | requests, mitmproxy, Frida, a cloud AI CLI | AI provider on every `gen` | The user's app session tokens, replayed | Captured request and response bodies | AI provider account |
| PersonaPlex | torch <2.5, sentencepiece, sphn, aiohttp, libopus | Gated HF download; optional Gradio tunnel when its token flag is given (`moshi/moshi/server.py:412-425`) | HF token | None in default operation | NVIDIA Open Model License acceptance |
| V1/V2 voice streaming | None | None | None | None | None |

**PersonaPlex server defects.** These matter only if a future V3 hosted its server, and they decide how it would have to be wrapped:

1. `moshi/moshi/server.py:479` calls `web.run_app(app, port=args.port, ...)` without a host, so aiohttp binds every interface; `--host` (`:359`) only feeds the log line at `:474`. A V3 trial must bind loopback explicitly, as `docs/reference/llamacpp-loopback-adapter.md` already requires of adapters.
2. `server.py:152-155` joins the client's `voice_prompt` query parameter onto the voice directory with `os.path.join`. An absolute or `..` value escapes the directory. Embedding files are then read by `torch.load(path)` without `weights_only` (`moshi/moshi/models/lm.py:977-979`), and the pinned `torch <2.5` defaults to full unpickling. A crafted `.pt` anywhere readable becomes code execution. A V3 wrapper must resolve the filename against an allowlist and pass `weights_only=True`.

**mimic.** Replaying another service's private API with captured tokens, and disabling an app's TLS verification, raise Terms-of-Service and account-safety exposure that Nexus should not take on as a feature. No explicit Nexus rule names traffic interception today (inventory search for "intercept", "mitm", "terms of service"); the registry policy's generation-as-service ban (`modules/coding/mcp/HubRegistryPolicyFilter.ts:8-9`, `STRATEGY.md:69`) already excludes its cloud generator.

**V1/V2.** Streaming TTS segments changes the sidecar response shape from one WAV to a sequence. Keep segment count and total bytes bounded, keep the audio runtime's JSON-RPC over stdio, and make cancellation on barge-in stop synthesis, not only playback.

## Prioritized adoption sequence

Ordered by the reverse-engineer-first rule: no skill-native artifact is needed, then local builds, then nothing vendor-bound. Within that, dependencies come first.

**Proposed v2.13 amendments (owner decision; the v2.13 plan file is unchanged):**

1. **D2, P0 (medium value, low effort).** In v2.13 Phase 1, adopt DigUp's fixture shape (`q`, `expect` with optional segment anchors, `tag`) and add its trap categories (exact duplicates, renamed copies, misleading extensions) to the hard-negative set.
2. **D3, P1 (medium value, low effort).** In v2.13 Phase 2, add the z-score plus coverage scorer as a third arm beside the two embedders, measured on the same set. Register its pass threshold with the existing gate before measuring. RRF remains default if it does not pass.
3. **D1, P1 (high value, medium effort).** In v2.13 Phase 3, add a reference-vector test for whichever embedder holds the job: fixed inputs, stored vectors, cosine >= 0.999, re-baselining only by an explicit command. This catches an Ollama or model-digest change that keeps the dimension but moves the vectors, which E2's identity check alone does not.

If the owner declines these for v2.13, they move unchanged to the front of v2.14.0.

**v2.14.0:**

4. **V1, P0 (high value, low effort).** Measure the existing voice loop end to end on the reference tiers: speech end to first audio byte, first audio to playback start, and full turn time, split by STT, model first token, model completion and TTS. Record cold and warm runs. This produces the number every later voice decision depends on.
5. **V2, P1 (high value, medium effort).** Cache the Kokoro pipeline per process, vectorize the int16 conversion, return Kokoro's segments as they are produced, and start synthesis on the first complete sentence of the streamed chat reply rather than the finished reply. Barge-in cancels pending synthesis. Acceptance: time-to-first-audio improves by a pre-registered margin over V1's baseline in the desktop app, with no change to final audio content. Voice is a desktop-only feature today (the VS Code extension has no voice loop, TTS or STT path under `src/`), so V2 improves that one channel and does not add voice to the extension.
6. **V3, P3 (medium value, high effort), conditional.** Only if V2's measured latency still misses a target the owner sets after V1, evaluate PersonaPlex at the 24 GB tier as a separate opt-in voice mode under the acceptance bar, with the loopback and `torch.load` fixes, a `licenseNote`, and an explicit statement that the mode does not use Nexus memory or tools. Do not install it as a default or a fourth runtime without a job-map entry.

Effort bands: D1 to D3 are additions to an existing evaluation; V1 is instrumentation; V2 is a bounded change across the audio runtime and both delivery channels; V3 is a feature plan of its own. Calendar estimates are withheld until V1 data exists.
