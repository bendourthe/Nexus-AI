Date: 2026-10-20. Plan: [v2.15.2 desktop triage](../plans/v2.15.1-batch2-desktop-packaging-composer-triage.md). Source item: `v2.2.3#DF-20`. Workspace: `C:/nx-close`, branch `feat/v2.15-archive-readiness`. This evidence covers the folder color repair; it does not close the whole minor or assert publication.

## Behavior

Chat's folder context menu now sends an explicit `chat.explorer.setFolderColor` request through the existing client, adapter, dispatcher and SQLite store. `Change color` applies the existing palette color `#9b5de5`; `Clear color` stores `null`. Both survive reopening the database. The existing `chat_folders.color` column is reused, so the change requires no database migration or reset. Only `color` and `updated_at` are updated.

The strict request accepts a nonempty folder ID and either a three- or six-digit hexadecimal color or `null`. Missing, malformed and unexpected fields fail validation. An unknown folder fails rather than reporting success. The client refreshes authoritative data after success; errors use the existing visible tree error. Shared tree adapters that cannot persist color expose neither action.

Folder identity, parent, name, icon, unrelated folders, chats and messages are preserved. The repair does not change undo or generated-media retention policy.

## Production Boundary

Separately from Vitest, a one-off driver was bundled with esbuild from the current production client, dispatcher and Chat runtime sources. It used the production sidecar's Node target, VS Code logger shim, native SQLite externals and `import.meta.url` transformation. The generated, ignored local artifact is `node_modules/.cache/folder-color-boundary/main.cjs`. Its exact execution command from `C:/nx-close` was:

```powershell
node node_modules/.cache/folder-color-boundary/main.cjs
```

It returned exit 0 and:

```json
{"result":"PASS","boundary":"production client -> invoke seam -> production dispatch -> SQLite","reopens":2,"set":"#9b5de5","cleared":null,"invalidColorRejected":true,"unrelatedDataPreserved":true,"realUserDataOpened":false}
```

The driver created a parent folder, child folder, unrelated folder, chat and transcript in a temporary database. It applied the palette color, closed and reopened the runtime, rejected an invalid CSS value, cleared the color and reopened again. Assertions checked the persisted color and clearing plus preserved parent/name, unrelated folders, chat and message data. It reset both `resetExplorerOps` and `resetChatExplorerRuntime` before each explicit `chatExplorerRuntime(tempDbPath)` initialization and after completion. The bridge returned serialized detached objects; the native Tauri invoke seam was replaced by production dispatch. No real user Chat database was opened, and the temporary database was removed after handles closed.

The generated driver is a local proving artifact, not a shipped CLI. The committed `desktop/tests/sidecar-node/folder-color-persistence.test.ts` preserves the same production boundary and temporary-runtime setup for repeatable verification on a fresh checkout; its command is included above.
