## Production flow

The seven production files reviewed were `modules/chat/storage/ChatExplorerStore.ts`, `desktop/sidecar/src/protocol.ts`, `desktop/sidecar/src/handlers.ts`, `desktop/sidecar/src/chat/explorerRuntime.ts`, `desktop/src/modules/chat/chatExplorerClient.ts`, `desktop/src/modules/chat/ipcChatExplorerClient.ts`, and `desktop/src/modules/chat/FolderTree.tsx`.

The persistent setter reuses `chat_folders.color` without a schema migration. Its parameterized update writes only `color` and `updated_at`; it rejects a missing folder rather than returning fabricated success. Both persistent and in-memory setters accept only null, three-digit hex or six-digit hex. The strict IPC request additionally requires a nonempty ID, rejects unknown properties and rejects missing/non-string color. This rules out arbitrary CSS strings through the new mutation surface. Existing folder creation behavior was not broadened by this change.

The method is registered alongside the existing Chat explorer operations and reaches the same runtime/store through the same dispatcher. It introduces no arbitrary file path, network destination, new listener, authentication bypass, database owner or privilege scope. The shared explorer setter is optional so Coding/Studio adapters can lack this capability. The raw Chat IPC client implements it explicitly.

The adapter waits for the mutation promise before invalidating its cache. A rejected mutation does not mutate a cached folder or invalidate it as if successful. FolderTree binds and invokes the capability, refreshes only after success, closes the menu and uses the existing visible error surface on failure. Color actions are hidden when the shared client lacks the setter. Clear uses null. Exact border color, durable clearing and unchanged stored/displayed color after rejected mutation are covered by focused DOM assertions. Pending pre-mutation reads are the separate cache limitation described above.

## Cache repair follow-up

Independent follow-up on 2026-10-20: the earlier P2 response-order finding is addressed in the current source. `createExplorerAdapter` now captures `cacheGeneration` when each tree read starts and increments it after every successful tree mutation. A stale read returns the current cached tree, or starts a fresh read when no current cache exists, instead of overwriting it. Failed mutations do not invalidate a valid cache. Delete and archive paths use the same invalidation function as create, rename, move and color changes.

From `C:/nx-close/desktop`, `npm exec vitest -- run tests/chatExplorerAdapter.test.tsx --reporter=dot` passed all 15 tests. The new controlled-promise regression starts an old read, saves a new folder color, caches the new tree, then completes the old response last. Both the old read's returned value and subsequent `getFolder` retain the new color. The explicit refetch branch also covers a stale response arriving while the current cache is empty; that second ordering is source-reviewed here and is not claimed as a separately executed regression case.
