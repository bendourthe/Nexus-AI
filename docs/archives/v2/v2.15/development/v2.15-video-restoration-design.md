# Video Lab Restoration Design

Status: reviewed future design, not implemented or authorized for implementation by this triage batch. The owner chose the recorded triage scope. This document preserves the proposed repair and its review requirements; it is not completion evidence.

## Owed Work

- `v2.3.0#DF-1`: a hydrated Video Lab turn restores its media path but loses Enhance eligibility. The output identity and source facts currently exist only in renderer memory. The obligation remains owed and must be carried with this reason and a future implementation task.
- `v2.2.6#DF-26`: cross-restart continuation lacks the original job identity. Restoring the prior-job request identity is related work, but actual conditioning on prior ending frames remains unproven. This obligation also remains owed; repairing persistence alone cannot resolve a frame-conditioning requirement.

## Current Flow

`StudioSessionStore` persists `StudioTurn.mediaRef` and optional usage in `extra_json`. `VideoLabPage` completion receives the generation output ID and SHA-256, constructs enhancement source bindings in memory, and keeps the last job ID in a ref. `hydrateSession` restores the transcript and last output path, clears enhancement sources, and resets that job ref. The existing remount test explicitly expects Enhance to be absent for a path-only turn.

`GenerationDatabase` already stores completed video job/output identity, content hash and workflow. `VideoEnhancementPersistenceAdapter.getGenerationOutput` checks the indexed completed video and workflow/provenance and returns authoritative dimensions and frame rate. Its existing file check is a stat, so action validation must additionally verify current bytes. No replacement generation transport, enhancement subsystem, media deletion or model download is proposed.

## Persisted Identity

Add an optional versioned video identity to an assistant video turn through the existing `extra_json`: job ID, output ID, SHA-256, generated/enhanced kind and, for a child, its parent job ID. Bound IDs and validate the hash. Do not treat persisted dimension or frame-rate hints as authority. Malformed optional identity must not discard an otherwise readable transcript. Existing path-only rows retain display/download behavior and do not acquire guessed action authority.

Derive a stable completion turn ID from the completed video job. Repeating the same session, role, media path and output identity returns the existing turn without incrementing turn count. Reusing that ID with conflicting session or identity fails. This makes child completion persistence idempotent across processes, rather than relying only on a renderer set. Hydration seeds `completedEnhancementJobs` from valid persisted child identities before polling; enhanced downloads remain distinct from original downloads.

## Session Ownership

Capture the submitting session ID once before the first enqueue await and carry it explicitly through segments, active-job state, persistence, completion and error handling. A job submitted in session A may finish and persist while B is visible, but cannot attach its output or errors to B. Avoid deriving ownership from the current selection after an await or from a temporary global job-session ref. An epoch or equivalent cancellation guard prevents a late hydration response for A from replacing B.

New session-scoped video requests carry `studioSessionId`; enqueue records it in the existing queue `threadId`, and children inherit source ownership. Session-scoped source and continuation operations require that exact live Video Lab session and job ownership. A scoped failure never falls back to the unscoped route. Requests without a session scope preserve the existing legacy/headless contract explicitly. Legacy rows or null-owned jobs cannot silently become session-owned merely because a caller supplies their path.

## Bounded Validation

Keep `listTurns` cheap: parse at most the requested bounded turn list and perform no per-turn file stat, hash or probe. A transcript may contain 500 turns; loading it must not trigger 500 unbounded reads. Unverified rows retain display/download, but cannot enqueue a scoped action until checked.

Use one lazy source-validation operation over the existing IPC transport, proposed as `studio.video.source` with `{sessionId, turnId}`. Derive the path and identity from that persisted assistant video turn, resolve the existing index/adapter snapshot, require the matching job ownership, compare the stored path and hash, and hash current bytes. Return authoritative dimensions, frame rate and output classification only after validation. The UI invokes this on an explicit action before opening an enabled enhancement panel, not automatically for every hydrated turn.

The proposed default budget is one active validation per sidecar, no waiting queue, at most 256 MiB per source, at most 5 seconds wall-clock and 1 MiB stream chunks. A second request returns a typed busy/retry result. Check size before reading, enforce cumulative bytes while streaming, use an opened file handle with pre/post file identity, size and modification-time checks, and close in `finally`. A timeout or runtime shutdown/reset aborts the read. Caller cancellation is supported only where the existing handler context supplies a cancellation signal; this design does not claim a new transport cancellation feature. Test the budget through injected limits and a controlled reader, rather than allocating huge fixtures.

An over-budget, missing, altered, corrupt, foreign or otherwise unverified source retains its transcript and cannot start the scoped action. The UI must explain that result and allow an explicit retry. Do not cache a successful UI check as enduring authorization: enhancement and continuation enqueue revalidate authoritative ownership and current bytes under the same budget. Preserve the original PNG/MP4 bytes throughout.

## Continuation

At session-bound enqueue, resolve `priorJobId` against the authoritative completed video job and indexed output, require the submitting session, and validate current bytes. If a caller supplies `lastFramePath`, reject a path conflicting with the authoritative output and fill the canonical path. For persisted-turn continuation, compare its stored identity too. Intermediate chain segments can use the authoritative owned prior job even before a transcript turn exists, while retaining the frozen submitting session ID.

This repairs persistence and request correlation. Current Python paths retain `continueFrom` metadata; the design does not establish real frame extraction or conditioning. That behavior needs its own observed proof and must remain stated as unproven until obtained.

## Implementation Boundary

Expected code ownership for a separately authorized implementation: `core/generations/StudioSessionStore.types.ts`, `StudioSessionStore.ts`; existing session and video schemas in `desktop/sidecar/src/protocol.ts`; narrow session/video enqueue handlers in `handlers.ts`; the session runtime and a small owned/injected validator; `desktop/src/shared/explorer/ipcStudioExplorerClient.ts`, `studioExplorerClient.ts`; `desktop/src/modules/video/VideoLabPage.tsx`, `videoClient.ts`, and enhancement client/panel scope plumbing where needed. Reuse the existing index, queue and adapter. Do not modify shared OCR, image recipes, historical evidence, media content, ledgers or migration receipts as part of this repair.

## Required Proof

- Complete and index temporary video bytes, append through the real session operation, close both generation and session databases, reopen new instances, load the session, mount a fresh renderer, and show that the checked Enhance action submits the same parent/output/hash and a follow-up keeps the same prior job ID.
- Prove that missing files, changed bytes, invalid workflow, an image pillar, foreign session/job ownership, corrupt optional identity and legacy path-only turns cannot start scoped actions. Confirm original bytes remain unchanged.
- Delay A's enqueue response, switch to B, complete A and verify only A is persisted. Delay A's hydration response behind B and verify B remains visible. Exercise multi-segment completion with the captured session and path.
- Poll the same successful child repeatedly, close/reopen and poll again; require one persisted child turn and one count increment. Check conflicting stable completion identity fails without overwriting an existing turn.
- Exercise byte, time, busy, abort and file-change budgets. Confirm transcript loading invokes no source reader and shutdown releases the active handle.
- Prove scoped continuation rejects foreign/stale jobs and conflicting caller paths, while existing unscoped headless requests remain compatible. Do not claim frame conditioning from request-shape assertions.
