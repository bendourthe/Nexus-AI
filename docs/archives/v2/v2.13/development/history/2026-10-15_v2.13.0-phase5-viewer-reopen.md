## Plan delta

**Disposition**: False assumption (resolved inside the phase).

**Evidence**: the plan and the Phase 1 baseline (`baseline-and-seams.md`: "Persistent StudioTurn records supply mediaRef") assumed generated images were persisted. In the code, image jobs return only `pngBase64` (`desktop/sidecar/src/handlers.ts`, job runner), the completion event carries no `outputPath`, and `ImageStudioPage` persists the turn without a `mediaRef`. A saved image could not be reopened after a restart, so the plan's Image done criterion was unreachable as written.

**Resolution**: T015 permits extending sidecar handlers "only as required to pass stable persisted studio turn identity"; writing each generated PNG once to an owned, content-addressed folder is that minimum, and the renderer already persisted `outputPath`. The plan text was not edited, because the run record binds it and an edit would void the recorded approvals. Displaying saved images through the sidecar, not by widening the Tauri asset scope, avoided a permission change the run is not approved for.

**Consequence for remaining phases**: Phase 6 commands can rely on persisted image turns with owned PNG sources and the same process-bound grant model; agent callers need their own caller and run ids rather than the UI's. Phase 7 must cover DF-3 (saved images outlive their session), WN-1 (no packaged-window driver) and QG-1 (two load-sensitive test timeouts), and refresh the handbook page that describes Image Studio.
