# v2.13 Phase 5 evidence

Phase 5 connects the existing Image Studio viewer to the Phase 4 recipe store. A persisted Image Studio image now keeps its adjustments, marks and full undo/redo history across closing the viewer and restarting the app; Chat attachments keep in-memory editing. Support tier: candidate (proven at the sidecar, component and Chromium-engine boundaries; the installed Tauri window is not driven, see WN-1).

## What changed

- **Saved images (precondition the plan assumed).** Image jobs returned only base64 PNG data and their turns were persisted without a `mediaRef`, so after a restart there was nothing to reopen. The sidecar now writes each generated PNG once, content-addressed, to `~/.nexus/generations/images/<sha256>.png` (`desktop/sidecar/src/studio/generatedImages.ts`) and sends `outputPath` with `png`; the renderer already persisted `outputPath` as the turn's `mediaRef`. A failed write keeps today's display-only behaviour.
- **Sidecar methods** (`studio.image.media`, `studio.image.edit.open|commit|revision|close`, `desktop/sidecar/src/studio/imageEditRuntime.ts`): share the studio session store's connection. Opening an image in the viewer is the human selection that issues a grant bound to this sidecar process, the image's session, turn and source hash; the grant is revoked on close and on session deletion and never leaves the process. Failures reach the renderer as `CODE: message`.
- **Core store**: `describe` (identity and verified bytes of a turn's owned PNG) and `revision` (stored revision only, for change polling).
- **Viewer** (`ImageViewer.tsx`, `useDurableImageEdit.ts`, `imageEditClient.ts`): shows the sidecar's exact source bytes; previews each gesture locally through the shared reducer; commits a slider drag once on release and each stroke, text, reset, undo and redo on completion, one at a time against the last acknowledged revision; says "Saving..." until acknowledged and "Edits saved" only after; on failure rolls back to the acknowledged state with Retry and Reload; on conflict asks to Reload; close waits for pending saves and stays open on failure; polls the stored revision every 2 s while clean to pick up edits made elsewhere (no push channel exists). An image the store cannot accept (not an owned PNG, over the 2048 x 2048 limit) opens in in-memory mode with "Edits to this image are not saved". Pointer points are clamped to the image. Export refuses, with a message, when sharpening cannot read the canvas back instead of saving an approximation.
- **Page wiring**: `ImageStudioPage` passes a per-turn cached editor to the viewer only for messages tied to an acknowledged persisted turn, and draws hydrated saved images from their bytes (the webview cannot draw a raw disk path and a failed draw wipes the bubble); a failed read keeps the stored path as before. The asset protocol scope was not widened.

## Verification Expectation (functional evidence)

1. **Sidecar restart** (real `sessions.db` file and PNG): open, commit adjustments, stroke, text and undo; close the store; a new store and new ops (a new process's run id) reject the old grant, reopen the same recipe, history and cursor (revision 4, undo and redo available), redo restores the text mark, and the PNG hash is unchanged. A changed PNG reports `SOURCE_CHANGED`; a turn without media `IMAGE_NOT_FOUND`; a file outside the owned root `FORBIDDEN`.
2. **Viewer reopen**: unmount and remount over the same stored recipe restores slider values and undo/redo availability; undo and redo walk adjustments and marks; a new edit after undo drops the redo branch.
3. **Pixels in the WebView engine**: `node desktop/tests/webview/image-edit-pixels.mjs` bundles the real viewer and opens it in headless Edge 155 (Chromium, the WebView2 engine), read over the DevTools protocol on loopback with a temporary profile. With brightness 120, contrast 130, saturation 70, sharpness 60, a stroke and a text mark:

```text
previewVsExport: differing 0, maxDelta 0
sharpening:      readback true, differing 464, maxDelta 122
original:        sourceSha256 == downloadedSha256 (9f13bb92...)
exportedType:    image/png
```

Not observed here: the installed Tauri window driven through generate, edit, quit, relaunch and export (WN-1). The text fixture uses the engine's default sans-serif; Phase 6 compares UI and command exports on this same runtime.

## Limits and decisions

- Grants left for a session removed through folder deletion are not swept, but every recipe operation first checks that the session and turn exist, so they grant nothing.
- A viewer opened before the new turn is acknowledged edits in memory; the next open is durable.
- Saved images stay on disk after session deletion (DF-3); the plan requires shared original media to be preserved.
