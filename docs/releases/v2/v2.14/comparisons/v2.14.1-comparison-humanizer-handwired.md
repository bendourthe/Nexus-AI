# Humanizer and Handwired Comparison

**Project**: Nexus
**Date**: 2026-10-16
**Baseline**: `develop`, `11fcc453`; clean working tree before this assessment.
Adoption target: v2.14.1
**Placement**: confirmed by the owner on 2026-10-16, after the finalized v2.14.0 voice and latency plan. This is assessment placement, not implementation or model-admission approval.
**Scope**: Humanizer model card and supplemental implementation; Handwired repository and the claims supplied with the comparison request.
**Disposition**: reuse existing editing skills; propose a bounded rewrite evaluation; defer Humanizer admission and Handwired integration.

## Recommendation

Nexus already has local drafting models and an installed editing-skill path. Start by evaluating those against the user's rewriting task. A second model is justified only by a measured improvement in useful rewrites with preserved meaning, acceptable memory and latency, and verified runtime behavior. Humanizer remains a candidate; no local inference or quality comparison was performed here.

Handwired offers a numeric-program builder and useful examples of reference-versus-compiled testing. It is not an automatic converter for arbitrary JavaScript, and its search and layout demonstrations address different workloads from Nexus's retrieval and image-editing surfaces. Keep its runtime out of the product until a specific user need and measured bottleneck justify it. These are assessment judgments against the local-first, single-GPU constraints in [STRATEGY.md](../../../../../STRATEGY.md).

## Claim assessment

### Humanizer

The card describes a local Gemma 4 12B fine-tune for English and Chinese rewriting. Fact preservation is a training objective. Its Q8 evaluation reports factual problems in 44 of 420 English rewrites, so preservation is not guaranteed. Detector results measure a different property and are not an admission criterion. Published memory figures are from a Mac and do not establish a Nexus Windows GPU fit. [Model card](https://huggingface.co/jialinyyzz/humanizer/blob/2e57b6528a4070c33f3e09ca24e3325a84272f68/README.md)

The prompt is a fixed completion format, with an 8,192-token operational budget for instruction, draft and rewrite. Recent GGUF chat templates select only the last user message and ignore system messages and earlier turns. A generic chat endpoint is consequently insufficient evidence of correct integration. Preserve the prompt fingerprint, EOS handling and sampler settings in any trial. [Prompt builder](https://github.com/sgaofen/humanizer-local-model/blob/83a597f07f1cda091360a0b5181e266eab15681f/humanizer/promptfmt.py), [usage guide](https://github.com/sgaofen/humanizer-local-model/blob/83a597f07f1cda091360a0b5181e266eab15681f/docs/USAGE.md)

The CLI separates prose from document structure and reports missing or added numbers and missing links. That is useful validation, but it cannot establish unchanged meaning, name-to-value associations, negation or qualification. [CLI](https://github.com/sgaofen/humanizer-local-model/blob/83a597f07f1cda091360a0b5181e266eab15681f/humanizer/hz.py), [text processing](https://github.com/sgaofen/humanizer-local-model/blob/83a597f07f1cda091360a0b5181e266eab15681f/humanizer/hz_text.py)

### Handwired

| Supplied claim | Finding | Consequence for Nexus |
|---|---|---|
| Converts ordinary JavaScript to a neural net | Developers manually append operations to a numeric `Circuit`; no tool converts existing JavaScript source | No automatic conversion of Nexus modules is proposed |
| Exact program representation | Equality is to specified FP32 calculations under declared contracts, not arbitrary JavaScript float64 semantics | Numeric bounds, rounding order and exceptional values require explicit tests |
| Fully differentiable software | The backward pass has explicit policies for discrete boolean and index operations; useful gradients are not universal | Do not infer that arbitrary branching software can be optimized safely by backpropagation |
| Browser operation without a GPU | The general runtime evaluates on CPU; the JSON-search demo uses WebGPU | CPU operation does not establish CPU performance for the GPU demo |
| Real-time search over 100,000 JSON files | The demo searches generated, bounded JSON documents, up to 512 code points each | No speed or quality conclusion about Nexus retrieval follows |
| Photos learn their arrangement | A small layout network is trained against edited rectangle targets | This is layout learning, a different job from single-image durable edits |
| Combine exact logic with an LLM | The root README proposes this direction | Nexus integration and model-quality benefit remain future work |

Evidence: [programming model](https://github.com/chenglou/handwired/blob/257856e3b221140acb4cc4460626b850c0bd4ff1/docs/README.md), [numeric and gradient contracts](https://github.com/chenglou/handwired/blob/257856e3b221140acb4cc4460626b850c0bd4ff1/docs/execution-model.md), [search workload](https://github.com/chenglou/handwired/blob/257856e3b221140acb4cc4460626b850c0bd4ff1/src/json-search/README.md), [learned gallery](https://github.com/chenglou/handwired/blob/257856e3b221140acb4cc4460626b850c0bd4ff1/src/learned-gallery/README.md), [root README](https://github.com/chenglou/handwired/blob/257856e3b221140acb4cc4460626b850c0bd4ff1/README.md).

## Prioritized adoption plan

This is a proposed sequence, not a phased implementation authorization. Order is skill-native reuse, then local builds or trials, with deferred and dropped items excluded.

1. **H1, reuse and baseline**: use the installed editing skills through the existing catalog. Preserve the original draft and compare output side by side. No new skill, model, runtime, picker entry or automatic answer postprocessor. Expected effort: a small evaluation-preparation task.
2. **W1, conditional reference testing**: if a later task proposes a numeric optimization, specify its plain implementation and boundary corpus before changing execution. Do not create a generic testing framework for this comparison.
3. **H2, preservation evaluation**: freeze a small bilingual corpus covering emails, reports, essays and posts, plus numbers with units, repeated values, dates, names, exact quotes, negation, Markdown links, code and tables. Include a swapped name/value example that retains every token but changes the fact. Compare original and output, including added facts. Start with existing tools and manual review; build a local literal checker only if repeated evaluation warrants it. Passing token retention must never be labeled proof of factual identity.
4. **H3, conditional model trial**: proceed only if H1/H2 reveal a useful unmet job. Freeze comparison criteria before inference. Pin the chosen quant and hash; verify exact prompt behavior, sampler controls, EOS, cancellation, long-document splitting and no non-loopback traffic. Measure host-specific memory and latency, and blindly review both model outputs for meaning and readability. A tie, inability to load correctly or lack of hardware is a retain/HOLD outcome. No detector score can substitute for these results.
5. **Admission decision**: only a demonstrated win can justify a catalog proposal under [model acceptance](../../../../reference/model-acceptance.md). A proposal must name the rewriting job and current holder, update the job map and integrity metadata together, and keep the specialist out of agentic model selection. The model's last-user-only template makes an agent-loop substitution inappropriate. A new server/runtime is a separate decision if existing adapters cannot serve the exact format.

For future implementation, likely reuse points are `core/skills/SkillCatalog.ts`, `modules/coding/llm/LocalAdapterRegistry.ts`, and the local clients. An evaluator can remain in release-scoped development tooling until a product need is demonstrated. Catalog/default changes would additionally touch `core/registry/catalog.json`, `core/registry/ModelCatalog.ts` where applicable, and `docs/reference/model-acceptance.md`; none changes in this assessment.

## Risks and exclusions

- Do not silently rewrite every Chat answer. That adds another model pass, changes user-visible wording and can alter factual content, code or speech timing.
- Do not import Humanizer's full app, CLI, model zoo or a second inference runtime for a comparison trial.
- Do not label a literal validator a complete fact checker. Names, associations, omitted qualifications and invented claims need broader review.
- Do not treat third-party detector scores as authorship evidence or writing-quality acceptance criteria.
- Do not replace `HybridRetriever`, SQLite FTS5 or existing image-edit recipes with an unrelated demo.
- Do not copy Handwired's private package, development toolchain or experimental dynamic-code paths into Nexus without a separately justified job.
- Refresh source revisions, installed skill availability, adapters, queue status and the model job map before any later implementation. Installed skills are machine-local observations and may differ on another installation.
