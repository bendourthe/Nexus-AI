**Found while verifying: a stale pin on a shipped model.** The first full run failed `tests/integration/NexusModelRegistry.test.ts` because the check, then applied to every `hf.co` entry with one GGUF pin, read this host's real pull of `lfm2.5:2.6b`: digest `02a8b7e1...`, against the catalog pin `79fdf003...`. Hugging Face confirms the current file is `02a8b7e1...`; the upstream file was replaced on 2026-08-19 (commit `b8b9fd82`, "Copy files from models/LiquidAI/LFM2.5-QAD-GGUF"), a day after the 2026-08-18 pin. Two changes followed: the check now applies only to entries that also pin a commit (`source.revision`), as the admitted entry does, so `lfm2.5:2.6b` installs exactly as before; and the stale value was corrected to the verified current sha256 (installer invariant test updated with the reason).
