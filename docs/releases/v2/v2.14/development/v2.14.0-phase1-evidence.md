### Voice baseline (ms, p50 / p95)

| Fixture | Transcribe | Model first token | Model complete | Synthesis | Time to first audio | Time to last audio |
|---|---|---|---|---|---|---|
| short, cold | 4836 / 5264 | 8411 / 9602 | 8631 / 9828 | 10044 / 11742 | 18876 / 20368 | 21176 / 22668 |
| short, warm | 4203 / 5484 | 7767 / 8887 | 7972 / 9094 | 2251 / 2850 | 10234 / 11920 | 12534 / 14220 |
| medium, cold | 4981 / 11637 | 20484 / 26905 | 23740 / 30151 | 22462 / 58314 | 45059 / 88466 | 78309 / 120766 |
| **medium, warm (reference)** | 6613 / 7292 | 20217 / 28590 | 23411 / 31762 | 15388 / 17804 | **38579 / 47642** | 70606 / 82669 |
| long, cold | 5180 / 6392 | 29508 / 38494 | 33883 / 43205 | 30469 / 36228 | 66587 / 73459 | 122884 / 126562 |
| long, warm | 6251 / 6884 | 30850 / 61226 | 35433 / 65557 | 23454 / 27569 | 59044 / 87923 | 113941 / 137948 |

Stage values for "model first token" and "model complete" are measured from the transcription request, so they include transcription. Inter-segment gaps are not measured in baseline mode because the baseline produces one segment.

**Reading of the baseline.** On the reference fixture, about 6.6 s goes to transcription (Whisper is rebuilt on every call), about 13.6 s more to the model's first visible token (the 12B Gemma reasons before answering), about 3.2 s to the rest of the reply, and 15.4 s to synthesizing the whole reply. Phase 2 removes most of the last two by speaking from the first sentence. Transcription and the reasoning delay remain, which is relevant to gate V-1 (2.0 s). The gates in `gates.md` were frozen before Phase 2 and are not adjusted for this.

## CI impact

- New Vitest file `tests/unit/scripts/measure-voice-latency.test.ts` runs in `npm test` (`full` profile) through the existing `tests/unit/**` glob. `desktop/tests/runtime-config.test.ts` runs in the desktop suite.
- New `tests/python/audio/test_audio_offline.py` runs in the existing `test-python-runtimes` job (`python -m pytest tests/python -q` with `NEXUS_AUDIO_STUB=1`); it imports neither Kokoro nor Whisper.
- New `scripts/installer/tests/test_voice_runtime_provisioning.py` runs in the existing `installer-tests.yml` job.
- The lock change adds four requirements to the provisioned venv. CI never provisions that venv, and pip-audit already covers `runtimes/audio/requirements.txt`; the new pins (`kokoro`, `faster-whisper`, `av`, the `en_core_web_sm` wheel) are not yet in that file, which is a candidate for the Phase 5 reconciliation.
- `scripts/measure-voice-latency.mjs` and the LFM probe need weights, a GPU and a running Ollama, so CI does not run them. No pipeline file changed; no remote CI ran.

## Limitations

- The packaged desktop app was not exercised in this phase. The installed runtimes copy under `%LOCALAPPDATA%\Nexus\runtimes` still has the old `engines.py` until the installer re-provisions; the measurement pointed `NEXUS_AUDIO_CWD` at the checkout. The packaged-app check belongs to Phase 2's Verification Expectation.
- The provisioned venv on this host was brought to the new lock by installing the four pins directly with pip (the same pins the provisioner installs), not by re-running the installer. A real installer re-provision is part of the Phase 5 installer rebuild.
- Ollama kept the chat model resident between cold runs, so "cold" covers the audio runtime and engine construction, not the chat model's load.
