## Human/manual testing suggestions

Only what the automated and scripted checks above cannot judge. Run these in the packaged Windows app built from this branch, with real hardware.

1. **Responsiveness with a real microphone**: turn on Chat's Voice loop, ask a three-sentence question, and note whether speech starts while the reply text is still appearing. The scripted medium fixture measured about 3.9 s; the question is whether that feels responsive in use.
2. **Sentence joins**: listen to a reply of five or more sentences through speakers and headphones. Note clicks, overlaps, or a change in intonation where one synthesized sentence hands over to the next.
3. **Barge-in feel**: start speaking over a reply. Note whether playback stops at once (scripted cancel was 26 ms) and whether the next turn starts cleanly.
4. **Cues in real replies**: ask for a short code sample and a small comparison table. Note whether "Code is on screen." and "Table is on screen." sound natural at those points.
5. **A long list**: ask for a 50-item list. It should be spoken in pieces without stopping early (the over-long sentence fix).
6. **First spoken reply after a reboot**: after a fresh boot, send the first voice turn. It should speak, after a longer wait (cold load), rather than fail.
7. **LFM2.5 24B-A2B in real work (M5)**: if you install the opt-in model from Settings > Models on a 16 GB GPU, use it for real coding tasks over the next two cycles and note where it beats or loses to the Nemotron offload build. Its admission rests on a golden-task A/B, not on real use.
