## Overview

Seven phases turn the comparison's E1/E2 and C1/C2 recommendations into bounded Nexus work. The embedding branch first measures the currently consuming memory path, then permits a separate migration and job-map decision only when evidence supports it. A failed, inconclusive or unavailable model evaluation is a valid retain-current-model result, not a reason to block the independent image-editing branch.

The image branch preserves the existing brightness, contrast, saturation, sharpness, brush and text features. It adds a small versioned edit recipe and complete history, connects the existing viewer to durable storage, then exposes the same commands and rendering through the current authenticated control surface. This plan adopts concepts from the four editors; it does not import their code or build hooks, replace React with egui, or implement an Adobe-compatible document format.

The plan is an assessment and execution contract, not implemented behavior. All net-new capabilities are candidate support until their phase evidence exists. Published claims may become supported only on the observed Windows packaged surface. Missing runtime or hardware evidence is written as not proven here.

## Goals First / Definition of Done

- **Target problem and persona**: the single-machine builder/creator in [STRATEGY.md](../../../../../STRATEGY.md) loses editable image state after closing the viewer and cannot ask the local agent to perform the same bounded edits. The maintainer also lacks project-specific evidence for changing an occupied embedding job.
- **Strategy grounding**: preserve the local-first and single-GPU principles. Use the strategy's proposed M2 resource budget and M3 zero non-loopback ordinary-use checks as acceptance constraints; durable reopen addresses M4 reliability and offers a concrete M5 real-work rehearsal. These metric proposals are not silently promoted into approved strategy.
- **Image done**: a persisted Image Studio image can be adjusted and marked, saved, reopened after process restart, undone/redone across adjustments and marks, and exported through UI and command paths with equivalent decoded pixels. Source byte hash stays unchanged.
- **Retrieval done**: publish a repeatable paired baseline/candidate report on a frozen corpus and recipe; choose retain or admit with measured quality, latency, memory, offline and terms evidence. Evaluation alone satisfies the retrieval goal when admission is declined.
- **Migration done, if admitted**: no mixed vector spaces; interrupted rebuild leaves old retrieval usable; activation and rollback restore the same source records and recipe identity without data loss. Do not tick implementation tasks as completed when the branch is skipped: record conditional task disposition instead.
- **Agent done**: discoverable current values, ranges, enabled state, revision, undo/redo availability and typed failure results; the authorized API and renderer share the same state transition rules and render function.
- **Delivery done**: local gates, packaged Windows behavioral evidence, independent goal review and final integration evidence exist. No release step precedes green merged integration.

## Pre-registered retrieval gate (owner accepted 2026-10-08)

Use a frozen held-out fixture with 100 labeled queries: 60 answerable natural-language-to-code/document queries, 20 hard-negative distractor queries and 20 genuinely unanswerable queries. Keep any threshold-tuning/dev fixture separate; never tune on held-out answers. Record source/chunk hashes, exact labels, model digest, prefixes, dimensions, normalization, runtime version and search/ranking recipe. Run the same corpus, chunking, ranking and context settings for both models.

The owner-accepted promotion gate is at least +5 percentage points recall@5 on the 60 answerable queries, a paired bootstrap 95% interval with lower bound above zero, p95 end-to-end retrieval latency no more than 20% above baseline, no increase in accepted nonempty retrieval results on the 20 no-answer queries using a frozen rejection rule (false-positive rate is accepted-result queries divided by 20; this is retrieval-only, without LLM answer grading), and zero invalid/mixed vectors. Report hard-negative results separately. Take at least 30 measured warm repetitions and 5 cold loads per workload; record p50/p95, peak RAM/VRAM, coexistence with the normal coding model and blocked non-loopback inference. Downloads occur only during explicit provisioning, before the ordinary-use offline check.

Phase 1 pins numeric resource ceilings from the existing reference host/tier policy and captures measured baseline before candidate installation; weights on disk are not peak memory. Admission to an all-tier default job needs evidence on every required supported tier, including CPU. If any required tier cannot be measured, the default takeover remains not proven and catalog/default changes are withheld. Evidence can justify a later narrower job proposal, but inventing a new opt-in job is outside this draft.

Context and terms are separate blocking evidence: conservatively test the supported 8K model-card budget; do not use a 256K runtime metadata value to take the existing 32K job. Resolve the checkpoint's Apache-2.0 versus model-card restrictions with authoritative distribution terms before a pre-ticked default. If unresolved, record HOLD, retain the current model and continue image phases. Phase 2 must record PASS, FAIL or HOLD for each gate, never a fabricated benchmark.
