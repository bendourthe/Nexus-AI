## Human/manual testing suggestions

Only what automated tests here cannot reach. Run on the packaged Windows build after integration:

1. **Saved image round trip**: generate an image in Image Studio, open it, move each slider, draw a stroke and add text, undo twice and redo once, close the viewer, quit Nexus, reopen the session and the image. Expect the same values, marks and undo/redo availability, "Edits saved" in the status line, and the original download identical to the first one.
2. **History after restart**: reopen an older Image Studio session from before this release. Expect images that existed on disk to draw (older turns have no saved file and may show nothing, as before).
3. **Failure honesty**: with a session open, delete its image file from `%USERPROFILE%\.nexus\generations\images`, reopen the viewer. Expect "Edits to this image are not saved" with in-memory editing, never a false "Edits saved".
4. **Agent edit with approval**: from a terminal, `nexus image-edit access` for that image (session and turn ids from Image Studio), approve it in the Ask inbox, then `describe`, `apply` a brightness change and `render` with `"mode":"export"` in the `--json` body. Expect the open viewer to pick up the change within a few seconds and an export under `%USERPROFILE%\.nexus\generations\exports` that matches the viewer's own Save.
5. **Deny path**: deny a second access request. Expect `status` to report denied and no grant.
6. **Chat attachments**: edit an image attached in Chat. Expect no save status line and in-memory editing as before.
7. **Field note for DF-v211-2**: if the document outline tools were used on real work, add the M5 DEVLOG entry; otherwise decide whether to remove them.
