## Source verification

### S1 tiny-voca

Apache-2.0 weights and code; 4,537,291 parameters; English only; 24 kHz mono; two fixed voices (F2, M2), no cloning. The waveform comes from a source-filter synthesizer, not a neural vocoder. Artifacts: `tiny-voca.pt` 18.2 MB (PyTorch, pickle-based), `onnx/model.onnx` 21.4 MB (opset 17, also runs in onnxruntime-web), GGUF variants from 8.7 MB, and a 5.4 MB phonemizer data folder under CMUdict and other source licenses. The card claims "about 70x faster than real time on four CPU threads", with no RAM figure. Its quality evidence is a Whisper WER "sanity check" on 8 to 16 clips and a leaderboard snapshot; "No formal listening test has been run."

The headline "never trained on real voices" is narrower on the card: both voices were designed from text descriptions with Qwen3-TTS VoiceDesign and recorded with Qwen3-TTS 1.7B Base. The training set is synthetic, but the card says nothing about Qwen3-TTS's own training data, and the license terms on Qwen3-TTS outputs were not checked here. The PyTorch path installs two packages straight from the author's GitHub (`dizione`, `tiny-voca`), which were not read.

### S2 Nemotron 3.5 Bolt E4B

Not new. The [v2.16.0 probe](../../../../archives/v2/v2.16/development/bolt-e4b-probe.md) recorded E-1 (availability) and E-2 (OpenMDW-1.1 license) as PASS and E-3 as HOLD: the official tag `nemotron-3.5-bolt:e4b-q4_K_M` declares `requires: "0.40.10"`, and the reference host's Ollama 0.32.15 refused the pull with an upstream 412. E-4 and E-5 never ran for the CPU or GPU-fallback slot.

The card adds no new Nexus evidence. It now reads GA 2026-10-23, Gemma-4-E4B-it base, "8B (4B effective parameters)", 64K context, tool calling with reasoning on by default. The headline "4GB" is NVIDIA's workload target, not an artifact size: the Hugging Face repo's only weight file is a 6.18 GB Q4_K_M GGUF, and the v2.16.0 probe measured the Ollama bundle at 7,908,812,809 layer bytes. The benchmark table is NVIDIA-measured and does not count under the acceptance bar. The Hugging Face repo is GGUF-only, so its Transformers and vLLM snippets likely do not load from it; the catalog route stays the official Ollama library tag, never an `hf.co/` pull.

The candidate seat is unchanged: the 8 GB chat-and-agentic default held by `gemma4:e4b`, which is Bolt's own base, and the cpu-tier agentic slots. Taking either needs local fit, speed, and five tool-call transcripts.

### S3 Qwen-Image 2.1 Uncensored Omni (ChatR Labs)

A community rank-128 LoRA ("Omni adapter", step 90,000) merged into `Qwen/Qwen-Image-2.1` at strength 1.0, then quantized. It is not abliteration; "uncensored" means the release adds no prompt filter or output checker. The adapter's training data is not described. License: Qwen Research License, which says "for research or evaluation purposes only" and bars commercial use without a separate license.

The headline "4.4GB" is the transformer only (Q4_K_M 4.47 GB; NF4 3.67 GB; NVFP4 4.2 GB). The card says "The text encoder, processor and VAE are not included"; its example workflow loads a Qwen3-VL-8B INT8 text encoder and a BF16 VAE from `Comfy-Org/Qwen-Image-2.1`. The v2.8.0 record put that Int8 encoder at 9.35 GB for the same base. Supported loaders are ComfyUI 0.39.0 (custom nodes) and Diffusers `QwenImage21Pipeline`. The card's own timings are on an RTX 5090 at 35 steps, with no figure for 8 to 16 GB cards. 268,540 monthly downloads does not count toward admission.

## Security assessment

### Source-security gate

All three pages are **CLEAR**: no agent-directed text, hidden instructions, or destructive commands were found in the rendered cards or file listings. These are rendered-page observations; CSS-hidden HTML cannot be ruled out. Bounded cautions, treated as data and not executed:

- S1 ships a pickle-based `.pt` checkpoint (the ONNX file is the safe format) and tells users to `pip install` from GitHub.
- S2's sidebar shows curl-pipe-shell installers for third-party tools (`llama.app`, Hermes Agent). None is used by Nexus.
- S3's root holds only GGUF and safetensors; the four subfolders were not listed, and its root Diffusers snippet references a missing `model_index.json`.

## Conflicts and exclusions

- **No global Ollama upgrade.** B2 inherits the November A3 approach: a side-by-side runtime on a separate port and store.
- **Occupied jobs.** S1 cannot take the TTS default and S3 cannot take an image default without local numbers; vendor and leaderboard figures do not count.
- **License.** S3's research license is allowed only as a disclosed opt-in and never as a default. S1 and S2 clear the permissive and unrestricted postures.
- **Hugging Face pulls.** S2's `hf.co/` Ollama snippet is not a catalog route; the official library tag is.
- **Explicitly not recommended**: S1 and S3 as catalog rows this cycle; any GGUF image loader or Qwen-Image pipeline added only to host S3.
