## Overview

The comparison found that twelve of thirteen sources end as declines, a retained deferral, or watch items. The one actionable source, EmbeddingGemma 2, already has a frozen evaluator from v2.13 whose run has been on HOLD as DF-129 for five releases, because the reference host's Ollama 0.32.15 refused the candidate pull with HTTP 412. The v2.15.1 triage forbids a global Ollama upgrade. This plan writes the declines into the living decision records and qualifies a side-by-side runtime (see `CONTEXT.md`) so the frozen evaluator can finally score the candidate.

The frozen evaluator cannot return an overall PASS: it hard-codes the hardware-tier, coexistence, offline, license-terms and context gates to HOLD (tracked as DF-130) and always recommends RETAIN. Only its measured gates (quality, latency, rejection) are computed. The plan therefore judges the run on the measured gates, and a win produces a migration proposal for a later plan, never an admission or a default switch. Changing the required embedder forces a reindex of every user's memory and a minimum-Ollama-version bump for every install.

Delivery is documentation plus one small code change: `scripts/evaluate-local-embeddings.mjs` gains a loopback-only endpoint option so it can address the side-by-side runtime. Success is four artifacts: updated `declined-models.md` and model-acceptance Qwen3.8 notes; a runtime qualification record (or a recorded qualification failure); the endpoint option with tests; and rerun evidence with the DF-129 closing decision. Phase 2 carries the most risk, because it is the only phase that downloads and starts a process on the maintainer's machine.

## Goals First / Definition of Done

**Problem and persona**: the solo maintainer keeps receiving model proposals that were already assessed, and an evaluation designed in v2.13 still cannot run, so DF-129 migrates every release. The user benefit at stake is concrete: `embeddinggemma-2:270m` is about 0.38 GB against the current required embedder's 0.62 GB, and its Apache-2.0 metadata would close the embedder's OQ-5 license-disclosure case in [model acceptance](../../../../reference/model-acceptance.md).

**Strategy fit, stated plainly**: no [STRATEGY.md](../../../../../STRATEGY.md) metric moves directly. Phase 1 lowers the maintainer's cost of re-assessing resubmitted models (closest to M5's intent of not building what was already rejected). Phase 3 is ledger hygiene plus a prerequisite for a later change that could reduce download size for M1 clean installs. The evaluator measures neither whole-runtime peak RAM nor the GPU budget, so M2 does not move.

**Bar for "worth a migration proposal"**: the frozen contract's quality, latency and rejection gates all report PASS. The contract fixed those thresholds in v2.13 before any score; this plan does not reinterpret them.

**Definition of done**:

1. `docs/reference/declined-models.md` has one row each for Flint-abliterated, TwIL-8B, Bark and the phonon refiner; the DeepSeek V4.1 row names the GSQ-RCO Coder artifact and the shared Maya reopen condition; the model-acceptance Qwen3.8 section records Arete-27B and the DSpine drafter as not admitted.
2. `docs/releases/v2/v2.17/development/v2.17.0-runtime-qualification.md` records either a qualified side-by-side runtime (pinned version, archive digest checked against an independently obtained checksum, Authenticode signer, extracted binary digest, port, model directory, loopback-only listener table for the whole process tree, default-instance version/process id/start time unchanged) or the qualification failure and its blocker.
3. If the runtime qualified: `scripts/evaluate-local-embeddings.mjs` accepts `--base-url` restricted to `http://127.0.0.1:<port>`, normalizes it to its origin, rejects every other form, keeps `http://127.0.0.1:11434` as the default, and records the endpoint as `report.endpoint`; focused tests cover acceptance and refusal.
4. DF-129 is closed in exactly one of three ways, applied by the coordinator: measured gates all PASS, replaced by one new DF entry holding the migration proposal (DF-130 still blocks admission); any measured gate FAIL, a declined row for `embeddinggemma-2:270m` with a reopen condition; no measured result, a dated watch entry with a concrete reopen trigger. It does not migrate to another release.
5. The side-by-side runtime's process tree is stopped and its binary directory and model store are deleted on every exit path, with the deletion recorded.

## Phase 2: Side-by-Side Runtime Qualification

**Goal**: A version- and identity-pinned Ollama runs on a separate loopback port with its own model directory and profile, the default instance is untouched, and the evaluator can address it; or the qualification failure is recorded and Phase 3 takes its HOLD exit.
**Prerequisites**: None (independent of Phase 1).
**Stability Gate**: `v2.17.0-runtime-qualification.md` shows owner approval of version and port, independent checksum and Authenticode results, a loopback-only listener table for the whole runtime process tree, unchanged default-instance version, process id and start time, and the baseline and candidate identity checks; if qualification failed, it shows the failure and the HOLD exit instead, and sub-task 2.3 is skipped.
**Verification Expectation**: With the runtime running per the record, `curl http://127.0.0.1:<port>/api/version` returns the pinned version, and `node scripts/evaluate-local-embeddings.mjs --contract docs/archives/v2/v2.13/development/embedding-eval-contract.json --validate-only --base-url http://127.0.0.1:<port>` prints PASS with the frozen hashes (this proves argument parsing and contract integrity only; reachability is proven by the `/api/version` read); `--base-url http://localhost:<port>`, `http://192.168.1.10:<port>` and `http://127.0.0.1:<port>/x` are each refused with `INVALID_ARGUMENT`.
**Recommended model tier**: strong
**Recommended effort level**: high
**Recommended verification effort**: high
**Rationale**: Starts a network-listening process on the maintainer's machine with supply-chain, bind-address, shared-profile, PID-reuse and GPU-interference edge cases; small code change but high consequence if done wrong.

#### 2.3 -- Add a loopback-only endpoint option to the evaluator

**Objective**: Let the frozen evaluator address the side-by-side runtime without weakening its offline guarantees. Runs only if 2.2 qualified the runtime.

**Failure modes**: malformed or absent input: a missing `--base-url` keeps `http://127.0.0.1:11434`; any value whose parsed hostname is not exactly `127.0.0.1`, whose scheme is not `http:`, that carries credentials, a path other than empty, a `?` or `#` (even empty), lacks an explicit numeric port, or whose canonical origin differs from the raw input, exits with `INVALID_ARGUMENT` before any network access (port 80 is intentionally unsupported because the WHATWG parser drops it; the runtime uses a high port). Unreachable or slow dependency: the existing `RUNTIME_REQUEST_FAILED` handling and 60 s request timeout apply unchanged. Conflicting operations: the existing host-wide evaluation lease and `HOST_BUSY` refusal apply to the chosen endpoint.

**Build class**: load-bearing.

**Prompt**:
> In `scripts/evaluate-local-embeddings.mjs`, replace the hard-coded `const baseUrl = "http://127.0.0.1:11434"` with a parsed `--base-url` option defaulting to that exact value. Validate with the WHATWG `URL` parser plus a raw-string check: scheme `http:`; no username or password; hostname exactly `127.0.0.1` (reject `localhost`, `[::1]`, `[::ffff:127.0.0.1]`, decimal, octal and hex IPv4 forms, and any uppercase or non-canonical spelling); explicit numeric port in the raw input; no path, query or fragment markers in the raw input; and `new URL(raw).origin === raw`.
