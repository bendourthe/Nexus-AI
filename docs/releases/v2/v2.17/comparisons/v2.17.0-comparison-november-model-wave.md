# November open-model wave comparison

Adoption target: v2.17.0

**Target confirmation**: owner selected v2.17.0 on 2026-11-10. **Baseline**: `develop`, `7eb21dfc588495124404ce78ef2a0d6d6ac5df6e`, package 2.16.1. **Scope**: thirteen supplied sources (one GPU tool, one embedding paper, seven model artifacts or announcements, four software projects), plus the EmbeddingGemma 2 Hugging Face metadata and Ollama library page added to verify the paper's availability. **Status**: assessment and prioritized adoption proposal; no implementation, installation, download or model qualification. Pinned revisions and scan verdicts are in [source receipts](v2.17.0-source-receipts-november-model-wave.json).

## Source verification

### S1 gpu-unlock

The upstream HEAD on 2026-11-10 is `7eb51bcc`, the same revision pinned by the [v2.16.1 comparison](../../../../archives/v2/v2.16/comparisons/v2.16.1-comparison-gpu-unlock-lfm3-ornith.md). That report's G1 decision (keep GPU unlocking outside the installer and ordinary operation; at most a separately authorized Linux hardware experiment) therefore stands without new evidence. The supplied summary's "RTX 4090 FP16 165 to 331 TFLOPS" is a peak dense BF16 matmul rate the README itself says is power-limited on large GEMMs; the README's own workload table reports 0-15% for GGUF in llama.cpp/Ollama and no LLM decode gain. Two facts matter for the reference laptop: Ampere is the only family listed as stable, and the README warns that laptops can silently re-lock when the dGPU powers down. Windows is unmaintained upstream.

### S2 EmbeddingGemma 2

[arXiv:2610.37364](https://arxiv.org/abs/2610.37364) describes a unified text, image, audio and video embedder with truncatable dimensions; its claim is "outperforming both specialist models and models two to twelve times larger", a range rather than the supplied "12x". The paper page names no benchmark suite. The [Hugging Face repository](https://huggingface.co/google/embeddinggemma-2) metadata declares `apache-2.0`. The [Ollama library page](https://ollama.com/library/embeddinggemma-2) lists `270m` (304-378 MB, text), `440m` (text and image), `570m` (text) and `740m`/`latest` (1.3 GB, text and image), 768-dimension native output with Matryoshka truncation to 512, 256 and 128, and an 8,192-token model context. Its examples are text-only; image input through `/api/embed` is listed per tag but not demonstrated, and audio and video are not offered through any Ollama tag.

Nexus's required memory embedder is `embeddinggemma` 300M (`core/registry/catalog.json`, 0.62 GB, 768-dimension, license "Gemma Terms of Use" with no `licenseNote`, one of the OQ-5 cases in [model acceptance](../../../../reference/model-acceptance.md)). The 270m text tag would be about half the download under a permissive license. That is a reason to measure, not to switch: the acceptance bar treats an embedder change as "a migration, not a swap", because every user's on-disk memory must be reindexed. The measuring tool already exists: [evaluate-local-embeddings.mjs](../../../../../scripts/evaluate-local-embeddings.mjs) with the held-out fixture in [tests/fixtures/embedding-eval/](../../../../../tests/fixtures/embedding-eval/).

Multimodal chat turns are indexed only by a text surrogate; [multimodalSurrogate.ts](../../../../../core/memory/multimodalSurrogate.ts) states "Bytes never enter memory." Image embeddings of user attachments would reverse that decision and are not proposed. A narrower uncovered job exists: the Image Studio provenance index ([GenerationIndex.ts](../../../../../core/generations/GenerationIndex.ts)) has no visual or semantic search over the user's own generations. That is a candidate opt-in job, gated on proving image input through stock Ollama and on a maintainer naming the need (M5).

### S3 DeepSeek V4.1 GSQ-RCO Coder

The [pinned card](https://huggingface.co/ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-Coder-GGUF/blob/54229d38d588a66d1c6cff08af7b281b9326c656/README.md) prunes 192 of 384 routed experts per layer (about 280B parameters kept). "1 bit per parameter" is about 1.05 bpw counted over the original transformer with removed experts at zero; the kept weights are about 2.06 bpw. The 72 GB figure is the transformer shards only; the Engram table adds 110.6 GB (disk-mappable), for 182.7 GB total. Stock llama.cpp b11870 or newer is stated; license MIT. Publisher figures: SWE-bench Verified 77.0 versus 81.2 base, LiveCodeBench v6 88.57 versus 89.71.

The [v2.16.0 decline](../../../../reference/declined-models.md) reopens DeepSeek V4.1 only for a small or distilled official Ollama variant fitting 24 GB; this artifact does not meet it. It is a second candidate for the same opt-in patient-tier trial the sibling [v2.17.0 DeepSeek comparison](v2.17.0-comparison-deepseek-decision-evals-reylo.md) records for the Maya GGUF, under the same reopen condition (maintainer-owned offload use case, disk budget, bounded A/B against `inkling-small`). No separate item is created.

### S4 phonon and the refiner

[phonon](https://github.com/Infatoshi/phonon) chains NVIDIA Parakeet TDT 0.6B v2 (CC-BY-4.0), a dictionary pass and a 1.7B correction model, then pastes into the active app. macOS on Apple silicon is the shipped platform; Windows is beta and Linux a preview. Its latency figures (about 30 ms streamed, 65 ms key-up to paste) are measured on an M4 Max over 40 dictations; no word error rate is published. The app is GPL-3.0; Nexus is MIT, so no code is copied. The [refiner card](https://huggingface.co/Infatoshi/phonon-refiner-1.7b) is LFM Open License v1.0 (free commercial use only below USD 10M revenue), English-only, and evaluated mostly on one speaker's private dictations by model judges that share the labeling spec.

Nexus already ships push-to-talk transcription into chat ([ChatPage.tsx](../../../../../desktop/src/modules/chat/ChatPage.tsx) voice loop with transcript provenance labeling) on `faster-whisper-large-v3`, the speech-to-text default on every tier. The license posture forbids creating a new revenue-capped default, so the refiner is declined. Parakeet could only take the STT default with measured numbers, and an English-only model cannot replace a 90-plus-language default; it is at most an English low-latency opt-in in `runtimes/audio`, which would add sherpa-onnx or an equivalent to that requirement set. Transcript cleanup itself can be done by the user's existing local chat model (skill-native) if a maintainer reports needing it.

### S5 Flint-abliterated

The [card](https://huggingface.co/orcarouter/Flint-abliterated-GGUF/blob/4d618d1cb1d7782d4b08762fb664487bf5e4d3c4/README.md) is a refusal-direction ablation of `RecursiveSI/flint` (39.8B total, about 2.5B active MoE, Apache-2.0). The "single 16 GB GPU" file is Mix-12G, which the card itself calls "noticeably degraded" (perplexity +20% versus BF16). Loading requires llama.cpp PRs #30928 and #30929; older Ollama and LM Studio releases will not load the files. The repository is gated. Coding and agentic benchmarks were not rerun after ablation, and refusal figures were measured on BF16, not the quantized files. Catalog policy requires provenance for any uncensored entry ([catalog.ts](../../../../../core/registry/catalog.ts)); that is satisfiable, but the runtime and measurement gaps are not. The base model's shape is a natural contender for the 16 GB MoE worker job held by `lfm2.5:24b-a2b`, which would be a take requiring a paired A/B like the [v2.14.0 job move](../../../../archives/v2/v2.14/development/lfm-ab-results.json).

### S6 TwIL-8B

The [card](https://huggingface.co/webAI-Official/TwIL-8B/blob/9563ba7dfb70eeca4a26654b195011cbf818e7d9/README.md) is a full-parameter SFT plus RL fine-tune of `ibm-granite/granite-4.2-8b`. "93% of frontier" is LiveCodeBench, measured on the verbose variant (81.6 against 87.8 for the best frontier row), with the version and date window unrecorded and competitor scores copied rather than rerun. The card states tool use and agentic tasks were not evaluated and GGUF builds were not used for the reported scores. The license is webAI Non-Commercial 1.0. The candidate job, the 8 and 12 GB coding-specialist fallback held by `qwen3.5:9b`, is an agentic job, and an agentic take needs a local tool-call transcript; there is none to produce.

### S7 Sakutto

[Sakutto](https://github.com/jammaru/sakutto) runs PLaMo 3 Translate 0.8B through wllama (WebAssembly llama.cpp) in Chrome or Firefox, with Chrome's built-in Translator as fallback. The model is under the PLaMo Community License, which requires registration for commercial use and caps it at 1 billion yen revenue. Nexus has no browser-extension surface, and text translation is already reachable through any local chat model; `faster-whisper-large-v3` also translates speech. Not applicable.

### S8 txtai

[txtai](https://github.com/neuml/txtai) (Apache-2.0, Python 3.11+) combines sparse and dense indexes, graph analysis, pipelines and smolagents-based agents, with optional hosted models through LiteLLM. Nexus already implements the core retrieval idea in TypeScript: [Bm25Index.ts](../../../../../core/memory/Bm25Index.ts), [DenseIndex.ts](../../../../../core/memory/DenseIndex.ts), [RrfFuser.ts](../../../../../core/memory/RrfFuser.ts) and [HybridRetriever.ts](../../../../../core/memory/HybridRetriever.ts), plus the SQLite FTS5 code graph. Adopting txtai would add a fourth Python requirement set for a job already held. Declined.

### S9 json-render

[json-render](https://github.com/vercel-labs/json-render) has a model emit a flat JSON spec constrained to a developer-defined component catalog (Zod-typed props, `catalog.prompt()` generating the system prompt), rendered progressively from a stream. Renderers span React, React Native, terminal, PDF, email and chat-platform cards. The useful idea for Nexus is the constrained-catalog pattern for agent result cards in the React desktop chat; it needs no dependency and can be rebuilt locally if a need appears. The Slack, Teams and Discord renderers send agent output to third-party platforms, which conflicts with M3 and the local-only posture. DF-3 and DF-6 in [v2.17 known gaps](../known-gaps.md) show the chat surface still has streaming and composer work outstanding, which should precede new rendering surfaces.

### S10 Inkling 2 Small

The [announcement](https://thinkingmachines.ai/news/inkling-2-small/), dated 2026-11-05, states 594B total and 17B active parameters, image input, closed weights at launch on Tinker, and "We intend to make the full weights available under an Apache 2.0 license next week" after external red-teaming. Two supplied claims are not on the page: per-token prices and the absence of a date (the page gives "next week" without a calendar date). Hosted-only models are not admitted ([declined Jev/Laya/Kev precedent](../../../../reference/declined-models.md)). Once weights exist, this is the natural challenger for the patient-tier frontier MoE job held by `inkling-small`, and it inherits that entry's open defects: OQ-2 and OQ-4 (no format binding, `inkling` not in `ModelFamily`) and DF-27 (multimodal unverified at the catalogued quant).

### S11 Arete-27B

The [Nous article](https://nousresearch.com/arete) describes SFT-only training of Qwen3.8-27B on about 52.8M tokens to remove state-aligned answers, with an Inkling teacher. Grading is by an LLM judge on Nous's own 803-prompt set; the Terminal-Bench-2.1 figure (70% versus 67%) is self-described as a non-standard configuration. Hugging Face metadata declares Apache-2.0; the article states no license. The acceptance bar's Qwen3.8 section lists Qwen3.8-27B as "not admitted" and says evidence for one row never transfers; a derivative inherits that status. If proposed, it contests the 24 GB coding-specialist fallback held by `qwen3-coder:30b` and needs local numbers.

### S12 Bark

[Bark](https://github.com/suno-ai/bark) (MIT, released 2023-04-20) generates speech, music and effects; its last commit is 2024-04-05. The full model needs about 12 GB VRAM, clips are about 13 to 14 seconds, and the FAQ compares audio quality to "a 1980s phone call". `kokoro-82m` holds the text-to-speech default. Music and sound-effect generation is not a job in the map; Bark could claim it only as an opt-in, and its maintenance status and quality make it a poor holder for a new seat. Declined.

### S13 Qwen3.8-27B DSpine

The [card](https://huggingface.co/aj9o9/Qwen3.8-27B-DSpine-b16-GGUF/blob/e27cc7dfe121a0c9327eb36a7cce82a0dfa9e3e6/README.md) is a community GGUF of Tencent's 16-token block drafter for Qwen3.8-27B (Alibaba's model; the supplied headline's "Tencent's 27B model" conflates the two). It requires the `dspine` branch of a llama.cpp fork. "125 tok/s" is temperature 0, short context, single sequence, on code (128.7) and math (122.8); prose is 41.6 and the mixed set 90.1 against 28.2 without speculation. Speed falls with context, and community results on other GPUs include slowdowns. Both the fork runtime and the unadmitted base model fail the bar. The method is worth watching: if stock llama.cpp or Ollama ships block drafting, a host-specific A/B for the occupied coding jobs becomes possible, consistent with the v2.17.0 DeepSeek report's "treat speculative decoding as an A/B on that host". [DF-7](../known-gaps.md) (live llama-server round trip not proven) is a prerequisite for any llama-server-only path.

## Security assessment

### Source-security gate

Every source received a pre-ingest verdict before its content was used; the receipts record each one. Twelve sources are **CLEAR**: no agent-directed text, hidden or obfuscated instructions, curl-pipe-shell installers or destructive commands were found in the fetched pages. gpu-unlock is **PROCEED-WITH-CAUTION**, as in v2.16.1, because it is a privileged kernel module installed with sudo and boot-configuration edits, not because injection was found. Agent setup snippets on several model cards (Hermes Agent, OpenClaw, Pi) and promotional copy on the Flint card were treated as data. json-render lists `AGENTS.md`, `.claude` and `.cursor` directories whose contents were not read. These are bounded observations of rendered pages; no repository, fork, installer, notebook or tensor was audited or executed.

## Conflicts and exclusions

- **Required-default change is a migration.** A3 must not alter `embeddinggemma` until a reindex plan exists; a better score alone does not authorize it.
- **Memory privacy decision.** Embedding user attachments contradicts `multimodalSurrogate.ts`; A4 is scoped to the user's own generations.
- **License posture.** The phonon refiner (LFM cap) and PLaMo (registration and cap) cannot become defaults. TwIL-8B's non-commercial license is allowed only as a disclosed opt-in, and it has no job to claim.
- **GPL sources.** phonon (GPL-3.0) and gpu-unlock (GPL-2.0) code is not copied into MIT Nexus; only ideas are assessed.
- **Runtime forks.** Flint (unmerged PRs) and DSpine (fork branch) depend on runtimes Nexus does not ship; both channels (desktop sidecar and VS Code extension) would need the same runtime.
- **Evidence transfer.** Arete-27B and DSpine are Qwen3.8-27B rows; nothing measured for one Qwen3.8 artifact transfers to another.
- **Explicitly not recommended**: gpu-unlock in the installer or app, txtai as a dependency, json-render chat-platform renderers, Bark, and any hosted-only Inkling 2 path.
