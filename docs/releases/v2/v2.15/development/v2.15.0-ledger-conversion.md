## Conversion results

Applied on 2026-10-19 with `node scripts/known-gaps/migrations/normalize.mjs --apply <ledger> --date 2026-10-19`, one file at a time in minor order: v1.17, v2.4 to v2.11, then the register. Each run parsed its output through the pinned adapter before writing. v1.18 to v2.3 and the v2.12 release ledger had no problem and were left byte for byte as they were.

### Inventory totals before and after

| Total | Baseline | After conversion |
|---|---:|---:|
| Ledgers in scope | 19 | 19 |
| Items | 326 | 402 |
| Open items | 226 | 301 |
| Problems | 204 | 0 |
| Register entries | 43 | 43 |
| Archived originals the register carries | 8 | 39 |
| Archived-only open items | 193 | 193 |
| Distinct open items | 256 | 256 |

Open items rose by 75: these are the original rows that are now entries (8 + 1 + 8 + 16 + 42). The distinct count did not change, because every new entry is either an item the register carries (counted once, with the register) or a register entry already counted from its row. The after-conversion distinct count is 42 open register entries + 5 open v2.12 release entries + 16 v2.15 entries + 193 archived-only items = 256.

Three register entries carry no archived original, because they were recorded in the register itself: `DF-v212-1`, `DF-v212-2`, `DF-v212-3`.

Repository-wide, only the legacy-cutoff ledgers still report problems: v0.7 1, v1.0 66, v1.1 38, v1.2 33, v1.3 4 (142 in total, the same as the baseline). Command: `python scripts/known-gaps/checker-adapter.py discover`.
