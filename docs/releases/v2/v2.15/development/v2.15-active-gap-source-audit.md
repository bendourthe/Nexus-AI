## Decision boundaries

The user's request authorizes completing remaining work and preparing truthful archive readiness. It does not manufacture historical evidence or authorize a signed approval record to be rewritten. A model deliberately declined under an accepted bar is not missing implementation merely because the ledger calls it deferred. Conversely, a new release-plan task that only inventories an unresolved shipped behavior does not complete that behavior.

The v2.15.0 triage explicitly requires owner acceptance for its proposed `close` items; without acceptance it migrated them. Those decisions remain visible below. The separate owner decisions concerning M5 real use, document-outline removal or narrowing, generated-media retention, agent redo history, model admission, and consequential CI/security settings must remain explicit. No blanket close or migration is recommended.
