Completion requires three published platform VSIX files, NexusSetup.exe and SHA256SUMS.txt. Every listed binary must match its downloaded checksum and version; each VSIX ZIP must have the expected extension manifest, platform target and runtime dependencies. The built Windows VSIX must activate in an isolated VS Code profile and exercise its local headless/CLI boundary. The built Windows installer must pass the repository's actual installer smoke flow in a disposable target, with its runtime inventory and provenance bound to the published binary. CI must build and validate Linux/macOS VSIX content on those hosts. Interactive Linux/macOS desktop installation, signing/notarization not already required by repository packaging, and GPU hardware acceptance on other hosts are explicitly outside this Windows-host acceptance matrix and remain honestly recorded limitations. A required job, download, checksum, Windows activation or installer smoke that is missing or failing blocks completion. Model admission separately requires both channel observations in T004 and cannot borrow package-only proof.
