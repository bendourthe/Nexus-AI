## Source verification

### GPU unlock

The [pinned README](https://github.com/Zagitta/gpu-unlock/blob/7eb51bccae0a0b7e599e084d971170e9a1e82d0c/README.md) describes a Linux pre-driver kernel module affecting FP16/BF16/TF32 tensor operations with FP32 accumulation. Its current throughput table differs from the supplied figures; those exact before/after numbers were not reproduced. Reported workload gains are community results, not controlled Nexus measurements. It reports 0-15% for quantized GGUF in llama.cpp/Ollama and no decode gain, so the headline is not a general twofold coding speedup. More throughput also does not add VRAM or establish professional-card equivalence.

The hardware selector state is volatile, but installation persists through packages, boot-image configuration and a kernel option that can reapply it. A power cycle is therefore not a complete software rollback. The README qualifies laptop power-state behavior and points to a separately maintained Windows port. Neither proves this Windows laptop supported.

The [build file](https://github.com/Zagitta/gpu-unlock/blob/7eb51bccae0a0b7e599e084d971170e9a1e82d0c/Makefile) invokes download, extraction and distribution-specific package paths. The [downloader](https://github.com/Zagitta/gpu-unlock/blob/7eb51bccae0a0b7e599e084d971170e9a1e82d0c/firmware/fetch_artifacts.py) uses HTTPS and versioned filenames, but its inspected fetch path does not verify content hashes and accepts an existing cached file. That observation is specific to this function; it does not assert that every packaging path lacks verification. The [firmware notice](https://github.com/Zagitta/gpu-unlock/blob/7eb51bccae0a0b7e599e084d971170e9a1e82d0c/firmware/NOTICE.md) separates module licensing from NVIDIA firmware terms and explicitly withholds a redistribution-approval claim. Do not copy this stack into Nexus or remove required notices.

### LFM3

The [pinned card](https://huggingface.co/LiquidAI/LFM3-1.7B/blob/ac2586a34f1a1c03329dbdcdefabd8b6478ddaa7/README.md) describes a 1.73B text-only model, a 256K advertised context window, a tri-hybrid architecture and XML function calls. It explicitly advises against agentic coding and complex multi-step reasoning. The [family announcement](https://www.liquid.ai/blog/lfm3) describes six 2B-class models; its comparisons do not establish universal equivalence to models six times larger. Other modalities are separate artifacts, not capabilities of this text checkpoint.

An [official Ollama tag](https://ollama.com/library/lfm3:1.7b-q4_K_M) and [publisher GGUF](https://huggingface.co/LiquidAI/LFM3-1.7B-GGUF/tree/bad5729bba61d076fff20d2548e62526665af215) exist. The [registry manifest](https://registry.ollama.ai/v2/library/lfm3/manifests/1.7b-q4_K_M) resolves to `b36a103fe2f8fbe9df2ceec88b9cfdf842dc04aaabe2b4677d1acf8e16570b5d`; its [content-addressed config](https://registry.ollama.ai/v2/library/lfm3/blobs/sha256:81e72b4beedcbf1665fc3dd660672e525481406973298d5452d394d863bbed11) requires Ollama `0.40.13` and declares an `lfm3` renderer/parser. The inspected host is `0.32.15`. This is a metadata incompatibility finding, not a captured pull refusal. No weights were downloaded.

The [license](https://huggingface.co/LiquidAI/LFM3-1.7B/blob/ac2586a34f1a1c03329dbdcdefabd8b6478ddaa7/LICENSE) retains commercial revenue restrictions around its USD 10M threshold (sections 1 and 5). Under Nexus's acceptance policy, this is not the permissive-license replacement sought by the v2.16 agentic trial. A future opt-in proposal needs accurate disclosure, a named job and measured usefulness. Neither advertised context nor weight-file size is a measured host memory budget.

### Ornith

The [pinned quantizer card](https://huggingface.co/mradermacher/Ornith1.0-9B-3MPER0RR-abliterated-GGUF/blob/2bb87c558bcbeaa0e1abb85523aa999d02689804/README.md) supplies static quantizations of a community derivative and labels its license MIT. It lists Q4_K_M at about 5.7 GB; that is not total inference memory. Its [immediate parent's card](https://huggingface.co/3MPER0RR/Ornith1.0-9B-3MPER0RR-abliterated/blob/684561499c11ac833956e267fbf43976b09a01ab/README.md) provides very little evaluation detail. Parent metadata identifies `Qwen3_5ForCausalLM`; the declared original, [Ornith-1.0-9B](https://huggingface.co/ornith-ai/Ornith-1.0-9B/tree/83dc1f5e24ef8527af019a6b3bf66ac0f1c2c999), has a different multimodal architecture declaration. Do not transfer vision or tool-call claims across those transformations.

The uncensored description alone establishes neither a new job nor better conversation quality. Nexus already has general chat defaults and a low-memory unrestricted-license alternative. A future trial should compare the selected quant against the actual job holder on the owner's conversational tasks, including consistency and instruction following. Verify the exact derivative's license chain, template, GGUF metadata and digest first. No local load, vision support, tool competence or quality advantage was proven here.

## Prioritized adoption sequence

1. **A1, skill-native, P1, low effort**: retain the named dispositions and exact reopen conditions. If implementation planning is requested, add proposal records using [declined-models.md](../../../../reference/declined-models.md), preserving existing decisions. Outcome: each proposal is discoverable without implying admission.
2. **A2, local reuse, P2, medium effort**: reopen only with an owner-selected low-memory chat task and a separately agreed compatible runtime. Pin the artifact and preregister memory, latency and task-quality gates against `gemma4:e2b` or the actual current holder. Measure CPU and intended GPU configurations separately, fixed-context cold/warm runs and errors. If agentic use is proposed despite the publisher caveat, require real tool/result/history round trips and coding-task evidence as separate gates. Keep HOLD on runtime failure or missing measurements. Update both registries, the job map and defaults together only after an admission decision.
3. **G1, local experiment, P3, high effort**: reopen only when a maintainer supplies a suitable Linux host, exact supported device and a specific compute-bound Nexus workload. Review package and firmware integrity first. Use fixed models, precision, seeds, power settings and runtime versions; record correctness, time, peak RAM/VRAM, thermals, power, boot/suspend behavior and rollback. Do not infer Ollama decode gains from a matrix-multiply benchmark.
4. **O1, local reuse, P3, medium effort**: reopen with a named conversational use case and evidence that an existing holder fails it. Qualify the exact Q4-class artifact, full memory at fixed context, repeated dialogue outcomes and the original model/derivative license chain. A passing runtime load alone does not justify a new catalog row.

Steps 2-4 are alternatives requiring their own scope decisions, not a commitment to implement all three. A2 and O1 would share catalog and admission surfaces if promoted, so no concurrent catalog writers are recommended. G1 remains outside product implementation. There is insufficient evidence for a phased implementation plan today; `/plan from-comparison` should begin only with a selected bounded trial and confirmed target.
