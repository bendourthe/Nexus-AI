## Frozen Installation Gate

T011 requires actual frozen-installer provisioning, while the existing smoke only booted the executable and validated bundled data. Local Windows Sandbox is unavailable, and desktop provisioning writes current-user registry/shortcut locations, so an environment-only local run would not protect the user's installation. The existing smoke now has an explicit InstallDesktop mode, invoked only by release packaging and the existing Windows rehearsal on a clean hosted runner. No product engine, ordinary CI topology, required check or coverage threshold changes.

Before launching any installer, the mode requires the hosted Windows environment and refuses existing Nexus app, runtime or configuration paths. It selects only the embedded desktop component and no models. The frozen install must complete desktop and runtime steps without failures. The independently invoked installed healthcheck must exit zero, emit real JSON with sidecar ok and a positive integer catalog count, and identify the newly provisioned Node executable. The receipt binds the unchanged outer installer SHA-256, installed executable, payload identity/version, provisioned Node version/hash and reviewed source. A separate failure receipt retains the failing stage; passing proof is written only after all assertions succeed.

The process waits are bounded to 600 seconds for installation, 60 for installed health and 15 for Node inventory, with task-owned live-process tree termination on timeout. Detached descendants are contained by the disposable hosted job; no general local sandbox or immediate detached-process confinement is claimed.
