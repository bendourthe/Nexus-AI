# Release Automation Evidence

## Changes

The shared [release-note extractor](../../../../../scripts/extract-release-notes.mjs) selects an exact semantic-version section across H1/H2 history, preserves subsections and complete fenced examples, and rejects malformed versions, missing/empty/duplicate sections and unfinished fences that could absorb older releases. The actual CLI writes a notes file only after validation. `release.yml` validates notes before packaging and passes the final file directly to publication, removing the multiline output-delimiter failure mode. This addresses v2.17 BG-9 at the code level; published-release proof remains pending.

Release preparation no longer runs automatically on main. The manual Release Readiness workflow has read-only contents permission, retains no checkout credentials and only validates artifact declarations and exact-version notes. The optional semantic-release configuration defaults to dry-run analysis/notes plugins, with version-writing, git-commit and GitHub-publication plugins removed. The artifact workflow remains the sole publisher. It requires an annotated tag, exact package/tag/source identity and reviewed main ancestry before packaging, then rejects a missing, lightweight or moved remote tag before publication. Three platform VSIX files, the complete Windows installer and their checksums remain required. This addresses v2.17 BG-8 at the code level; actual integration and publication proof remain pending.

## CI Impact

Release automation is this phase's explicit deliverable. Only the two release workflows and optional preview configuration change. Existing validation/packaging dependencies and checksum requirements remain. The new tests join the existing root Vitest discovery. Non-final work stays local; no push, remote CI, tag or release occurred in this phase. Comprehensive root/desktop validation, terminal pipeline reconciliation and package/runtime acceptance remain final-phase duties. The existing Vite ESM/CommonJS configuration warning remains visible and does not fail the focused runs.
