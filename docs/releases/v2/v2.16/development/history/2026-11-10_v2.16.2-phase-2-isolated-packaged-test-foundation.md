## Troubleshooting

- WebView2's debugging server never appeared as `LISTENING` in `netstat`; its socket shows as the server end of an established connection. The owner lookup accepts that state for the port's local address.
- The first in-page IPC call can wait while the sidecar starts; each attempt is now bounded and retried.
- A scripted edit of `launch-probe.mjs` failed its anchor assertion because of escaping, so nothing changed; the change was then made with the editor and rerun.

## Plan delta

**Disposition**: no blocking delta.

- **Evidence**: B3 passed through the real owned process boundary on the pinned executable; ABI was proven by the packaged native module under the provisioned runtime.
- **Clarifications**: the plan's `launch-probe.mjs` prompt implied a listening socket; the observed WebView2 server state differs, and the target check proves ownership by the port's local socket instead. The app's GPU telemetry starts console children (`nvidia-smi`, `powershell`); the job contains and ends them, and the product launch options stay outside this plan.
- **Consequence for remaining phases**: Phase 3 reuses `launchOwned`, `seedOwnedProfile` and the snapshot checks, adds the viewer edit, save, owned restart, read-back and pixel checks to `image-edit-flow.mjs`, and must rebuild and re-pin the executable if any product file changes.
