## Functional Smoke

The packaged sidecar (`target/release/sidecar/dist/main.js`) was started under the app's own provisioned runtime (`%LOCALAPPDATA%/Nexus/runtime/node/node.exe`, v22.11.0, ABI 127) with `HOME`, `USERPROFILE` and `NEXUS_WORKSPACE` set to a new temporary folder and an unreachable proxy so the first-launch Hub download fails fast. After `[nexus-sidecar] ready`, one JSON-RPC `commands.list` request returned:

```json
{"ok":true,"catalogPresent":false,"commands":[{"name":"creative-brief","description":"Create or reopen a local creative brief, then draft baseline-plus-delta image requests that keep confirmed facts and reference files unchanged","source":"builtin"}],"hubCatalogCreated":false,"error":null}
```

Expected and observed match: with no Hub catalog, the packaged app offers the bundled skill as a built-in, and no catalog folder was created. The temporary home was removed afterwards. Running the same bundle under the shell's Node v24 failed with `NODE_MODULE_VERSION 127 ... requires NODE_MODULE_VERSION 137`; that is the expected ABI pairing with the provisioned runtime, not a defect.

Run-time `/creative-brief` resolution in the sidecar (Hub precedence, missing and malformed bundled files, real prompt-injection scanner, `builtin` hook namespace) is covered by `desktop/tests/bundled-creative-brief.test.ts` against the source modules.

## Fixture Rehearsal

`tests/unit/skills/creativeBriefFixtures.test.ts` parses the confirmed brief and checks each of the three request drafts: the baseline is unchanged, `"LANTERN COFFEE"` stays in `fixed_text` and the baseline, the reference entry equals the brief's row, and each delta is distinct. Drafting is refused for the changed-reference brief (`changed ../assets/logo.png`), for a brief whose reference file is missing (`missing assets/logo.png`), and for the incomplete brief.
