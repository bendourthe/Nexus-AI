## Overview

The seeding comparison kept two items. DOC-1 records that CLM-8B (open, Apache-2.0, ranks candidate actions, needs vLLM plus a second service) is not admitted, that the PageIndex package and cloud are not adopted, and that AIRI was re-checked through 0.12.0-beta.5 with nothing new to take. PI-1 reverse-engineers the one PageIndex idea that fits Nexus: a tree per document that an agent walks, then reads one section.

The defect behind PI-1 is in the code today. `parse_document` is capped at 50 pages from page 1 in both channels (`PARSE_DOCUMENT_MAX_PAGES` in `src/tools/handlers/parseDocument.ts`, and a separate `HEADLESS_PARSE_MAX_PAGES` in `modules/coding/runtime/headlessTools.ts` for the sidecar). The per-page text the OCR runtime returns is dropped at the parser seam (`core/documents/headlessOcrParser.ts` returns only engine, text, markdown, pageCount). The optional memory ingest (off by default) keeps 8,000 characters then `[truncated]`. The OCR runtime has no markdown or text kind, so a plain `.md` file cannot be parsed at all.

Design stance, set by the maintainer: Nexus is a platform, so the feature handles documents generically rather than for named files. Any input the platform can read gets an outline: real headings when a per-document quality check says they are trustworthy, otherwise labelled page or character windows, so the tools never dead-end. Sizes follow the active model's effective context window, not fixed constants. The tools ship in both delivery channels (desktop app sidecar and VS Code extension), always.

Design rules fixed by the plan review (see [plan-review-findings.md](../development/plan-review-findings.md)): document text is never persisted by the outline cache; section reads re-extract text on demand (with a small in-memory, process-local snapshot), and staleness is judged on the raw file bytes, so non-deterministic OCR cannot cause a false "document changed". The file cache stores structure, offsets, titles, and per-node content anchors (hashes, never text), and only for extractors measured deterministic in Phase 2; output from any other extractor lives only in the in-memory snapshot and expires, after which the agent calls `document_outline` again. A slice is served only after its node's anchor verifies against the text it is read from, and an id from another revision always fails closed.

Phase 1 writes DOC-1. Phase 2 measures what the parser gives a tree builder and resolves two decision tickets. Phase 3 opens the parser seam and builds the outline core. Phase 4 adds the tools in both channels, the security screening, and node summaries. Phase 5 is a directional local smoke test; the flag stays off regardless of its result. Phase 6 is the mandatory final phase and also addresses the two carried CI gaps.

Phase 1 alone is an acceptable stopping point. If Phase 2 triggers its stop rule, Phases 3 to 5 are replaced by one known-gap row and the Goal reduces to DOC-1 plus the CI gaps.

## Goals First

**Target problem**: A solo builder who asks a local agent about a long document of their own gets a capped read or a truncated memory row, so the answer depends on luck about which pages fit. The hosted answer (PageIndex Cloud, or its local mode with an OpenAI key) would send the document to a third party, the cost `STRATEGY.md` section 1 says Nexus exists to remove.

**Persona**: The solo builder (`STRATEGY.md` section 2, primary) for PI-1. The maintainer (secondary) for DOC-1 and the CI gaps.

**Pillar**: Agentic AI Coding, rank 1 in `STRATEGY.md` section 4, because `parse_document` is a coding-engine tool registered in the sidecar. The user story is the solo builder asking the coding agent about a manual, spec, or report in their workspace. Chat pillar exposure is out of scope.

**Definition of done**:
1. `docs/v2/v2.11/known-gaps.md` has a new row, DF-v211-1, that contains the phrase "not admitted, no catalog row" for CLM-8B and also names the PageIndex package and cloud and the AIRI re-check.
2. With `nexus.coding.documentOutline.enabled` on, in both the desktop sidecar and the VS Code extension, `document_outline(path)` returns a tree for every input type the platform can read. The result reports `structureSource` (headings, page windows, character windows, or mixed), `pagesParsed` versus `pageCount` with a `partial` flag, and `treeHash`. `document_read_section(path, node_id, tree_hash)` returns that section's text with its page range, and a stale `tree_hash` returns "document changed, call document_outline again".
3. Every document-derived string the tools return (titles, ids, filenames, section text, summaries) is screened, secret-redacted, and wrapped in the untrusted-content delimiter with a provenance label. Output sizes are derived from the active model's effective context window, with a conservative default when it is unknown. The tools open no non-loopback connection, proven for the whole process tree.
4. `docs/v2/v2.11/development/outline-eval.md` holds directional counts for four arms on at least two tool-calling local models, or a known gap names why a run was not possible. The flag default stays off in v2.11.0 whatever the numbers say; promotion criteria with numeric thresholds and a dated M5 review (DF-v211-2, owner: the maintainer) are recorded.
5. CI-v251-1 and QG-v270-2 are each addressed with explicit per-change approval, or the declined change is recorded as a known gap with an owner.

**If the Phase 2 stop rule fires**: items 2, 3 (tool parts), and 4 are waived; DF-v211-2 instead records the measured reason the route was not viable; 6.2, 6.3, 6.7, and 6.8 drop their tool-specific content; the Goal for 6.7 is DOC-1 plus the CI gaps.

**Key metric**: STRATEGY M3 is protected, not moved: the tools open no non-loopback connection. STRATEGY M5 applies directly: the tools ship default-off, and "use" means one session-history or DEVLOG entry that cites a workspace document hash and the answer obtained. **Non-goals** (each with its reason):
- no `pageindex` package, PageIndex Cloud, cloud OCR, or MCP server: hosted processing of user documents (MCP Registry Policy).
- no CLM, vLLM, or `clm-serve`: a second runtime and a second resident 8B model on the single GPU.

### Sub-tasks

#### 3.1 -- Parser seam

**Objective**: Carry per-page data to the outline layer per decision 2.3, in both channels' parser types.

**Failure modes**: A runtime reply without `pages` yields an empty array and `pagesParsed` of zero rather than an error; a reply whose `pages` length disagrees with `pageCount` sets `partial: true` and is never padded; existing callers that ignore the new fields must see byte-identical results; the file is read once into memory, hashed, and the same buffer is handed to the parser, so the parser never re-opens the path.
**Build class**: load-bearing.

**Prompt**:
> Implement decision 2.3. Extend `ParsedDocumentResult`, `DocumentParser`/`BytesDocumentParser`, and `core/documents/headlessOcrParser.ts` to carry `pages`, `pagesParsed`, and `partial`, and add the outline-path entry point with its higher cap. Make the equivalent additive change to `HeadlessDocumentParser` in `modules/coding/runtime/headlessTools.ts` without touching `HEADLESS_PARSE_MAX_PAGES` for `parse_document`. Assert that `parse_document`'s default output is unchanged in both channels.

#### 3.2 -- Deterministic tree builder

**Objective**: Build the tree with no model involved, for any input, bounded in time and size.

**Failure modes**: Absent or `null` markdown falls back to page windows then character windows and says which `structureSource` it used; skipped heading levels attach to the nearest ancestor; duplicate titles get distinct ids derived from the global document-order ordinal; `#` lines inside fenced or indented code are not headings; a literal page-marker string in the body is escaped and never treated as structure; builds are iterative (no recursion), check a CPU-time budget, and cap node count, depth, title length, and total serialised outline size, reporting `truncated: true` with a continuation hint; window nodes carry titles and ids generated only from numeric ordinals and offsets ("Pages 51-60"), never from document text; slicing never splits a UTF-16 surrogate pair.
**Build class**: load-bearing.

**Prompt**:
> Create `core/documents/DocumentOutline.ts` (vscode-free; `core/**` must not import `modules/**`). Export `OutlineNode` (`id`, `title`, `level`, `startPage`, `endPage`, `charStart`, `charEnd`, `children`, optional page fields, `anchor`: a SHA-256 over the full normalised text of the node's span (so interior drift is detected; the span, not the size-capped slice, is hashed), folded with the ordered per-page text hashes for page-anchored nodes into the one digest; anchors never store text). Node ids are `<revision>-<stable>`, where `stable` is a hash of the ordinal and title path and `revision` is the first 8 hex characters of the tree's integrity digest, computed over the canonical structure with ids excluded (offsets, titles, anchors, schema version) so the id check is not circular; an id from a different revision always fails closed and is never remapped and `buildOutline(input, limits)` where `input` is `{ indexedText, textKind: "markdown" | "text", pages?, kind }` and `limits` holds only the hard safety caps (node count, depth, title length, serialised size, time); the model-context budget is applied separately at presentation time by a pure function, so the cached tree does not depend on the active model. #### 3.3 -- Section reader and structure-only cache

**Objective**: Return one section safely, and avoid rebuilding a tree for an unchanged file, without ever persisting document text.

**Failure modes**: A cache file that is corrupt, from another schema, or that fails strict validation (offsets beyond the recorded `textLength`, ids not recomputable from the ordinal and title path, an integrity digest over the canonical structure that does not match, over-long strings, node count over the cap) is discarded and rebuilt; a changed source file changes the key and misses; two overlapping builds for the same key share one promise (single flight), so a second caller never sees `DOCUMENT_PARSER_BUSY`; two writers never interleave (unique temp name, then rename); any write error degrades to no cache with a logged warning; a changed file (stale `treeHash`) returns "document changed, call document_outline again"; a tree whose extractor is not recorded as deterministic in decision 2.4 (including any unknown engine id or version) is `ephemeral`: it is never written to the file cache and lives only in the in-memory snapshot, and a read after the snapshot expires returns "outline expired, call document_outline again", which re-extracts, builds a new revision, and warms the snapshot (`document_outline` reuses a still-live snapshot with the same `treeHash` instead of re-extracting), so there is no rebuild inside a read and no way to loop; for a deterministic extractor, a re-extraction whose text fails the requested node's anchor (no length tolerance anywhere) discards the cache entry and returns "call document_outline again", and that call replaces the entry with a new revision; an id from a different revision always fails closed, with no remapping; an outline for a file the secret-path denylist refuses is never built or cached.
