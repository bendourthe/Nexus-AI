## 2. Chronological Steps

### 2.1 Parser seam (T009)

`BytesDocumentParser` (`core/documents/headlessOcrParser.ts`) now returns `pages`, `pagesParsed`, and `partial`. `ParsedDocumentResult` (extension) and `HeadlessDocumentParser` (sidecar) gain the same fields as optional, so `parse_document` ignores them. `HEADLESS_PARSE_MAX_PAGES` and `PARSE_DOCUMENT_MAX_PAGES` stay 50. The outline path's cap is `OUTLINE_MAX_PAGES = 200` (decision 2.3, Option B).

### 2.2 Builder (T010)

`core/documents/DocumentOutline.ts`: fence-aware markdown headings and space-insensitive numbered headings; the run-time quality predicate (`assessHeadings`); page or character windows with numeric-only titles; oversized sections split into windows (`mixed`); iterative build with caps on nodes, depth, title length, serialised size, and CPU time; surrogate-safe boundaries; full-span anchors folded with page digests; ids `<revision>-<stable>` with the integrity digest computed with ids excluded; `presentOutline` applies the context budget at presentation time.

### 2.3 Reader, cache, orchestration (T011)

- `core/documents/SectionReader.ts`: fail-closed checks on tree hash, revision, text length, and anchor; no tolerance.
- `core/documents/OutlineCache.ts`: strict validation, structure-only entries, screened titles only, size cap with oldest-first eviction, purge; `TextSnapshotCache` holds text in memory only, bounded with a TTL.
- `core/documents/OutlineSession.ts`: per-engine determinism table (direct, docx, rapidocr on CPU); single flight; snapshot reuse; ephemeral outlines never persisted and expiring fail-closed; drifted deterministic re-extraction discards the entry.
- `core/storage/OutlineFileStore.ts`: `~/.nexus/outline-cache`, hex-only names, unique temp file then rename, one retry on Windows `EPERM`/`EBUSY`/`EACCES`.

## 3. Deviations

- `# DEVIATION:` `readSection` also takes the page list, because page-bound anchors fold the page digests.
- `# DEVIATION:` an orchestrator (`OutlineSession`) was added in core so the failure modes in 3.3 (snapshot reuse, expiry, drift, file swap) are testable without the tool layer.
- `# DEVIATION:` titles are screened during the build (an injected `screenTitle`), so the digest covers the screened title; the cache refuses any entry whose titles do not pass the same screen.
- The store retries a rename once on Windows sharing errors; a concurrent-write test run showed `EPERM`.

**Escape-decoding defect found and fixed (classified ENV, then IMPL).** `\uXXXX` escapes for printable Unicode written through the authoring tools arrived in the files as literal characters, and the repo's Unicode sanitizer then stripped them. That broke the control/bidi regex in `DocumentOutline.ts` (a range out of order, caught by the build), and silently reduced three BOM checks to no-ops: `normalizeTextSource`, the measurement script's direct-read path, and the generator's `bom-crlf.md` fixture (the committed fixture still had its BOM, so the generator had drifted from it). All of them now build the characters from code points (`String.fromCharCode`, `BOM_AT_START`). A new test asserts the generator reproduces every committed fixture byte for byte; the measurement table from Phase 2 is unaffected because it ran before the sanitize pass.

Two test-side fixes during the troubleshooting loop, both classified TEST: the CPU-budget test's fake clock advanced too slowly for the 256-node check interval, and the drift test expected a snapshot where the design deliberately rebuilds fresh.

## Plan delta

**Disposition**: Incomplete (non-blocking).

**Evidence**: The plan's 3.3 signature for `readSection` omitted the page list that page-bound anchors need, and it did not name where the snapshot, expiry, and drift logic lives; `OutlineSession` now holds it in core. The OCR runtime reports no engine version, so the cache key uses the engine id, device, and a fixed version label (WN-v211-1).

**Consequence for remaining phases**: Phase 4's shared tool module calls `OutlineSession` rather than re-implementing these rules; its extractor adapters supply the engine identity.
