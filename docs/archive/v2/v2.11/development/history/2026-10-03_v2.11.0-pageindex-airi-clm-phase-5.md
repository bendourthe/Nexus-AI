### 2.3 Calibration finding 1: no tool calls at all

The first two-question calibration made zero tool calls in arms A, C, and D on both models. Diagnosis, step by step:

1. The headless system prompt taught every model the Gemma call syntax with a JSON-argument example that no parser reads. Fixed with `toolCallSyntax(format)` in `modules/coding/llm/parseAgentToolCalls.ts`, tested so each format's example parses back with its arguments.
2. Live replay showed the deeper cause: Ollama 0.32 parses Gemma 4 and Qwen 3.5 call tokens itself and returns them in `message.tool_calls` only when the request carries `tools`. Without `tools`, qwen3.5:9b answered without calling anything and gemma4:12b returned empty text. With `tools`, both returned structured calls on the first turn.
3. No client read `tool_calls`. The VS Code extension already sent `tools`, so on this Ollama every call it got back was silently dropped.

Recorded as blockers 3 and 4; the maintainer chose to fix the root cause in v2.11 both times. The fix:

- `LLMStreamChunkSchema` keeps `message.tool_calls`.
- `parseAgentToolCalls(text, format, nativeCalls)` returns native calls when present, else text calls, never both, so one call cannot run twice.
- `AgentLoop` and `HeadlessAgentSession` collect native calls from the stream; the headless loop also sends `tools`, in the same schema the extension builds.
- `LmStudioClient` and `headlessOpenAiClient` assemble OpenAI-style streamed calls through the shared `OpenAiToolCallAccumulator`.

Live check after the fix: qwen3.5:9b made 6 tool calls and answered; gemma4:12b chained 5 calls. Both had made zero before.

### 2.4 Calibration findings 2 to 4: harness and scorer

- Arm A paid OCR inside its 4-minute window while arm C had been warmed. The harness now extracts every PDF and DOCX at both page caps before any timed question; the cold cost is reported separately (M2).
- A run stopped by the time limit was labelled "no-answer"; it is now a timeout, and hitting the iteration cap is an error.
- OCR keeps some spaces and drops others, so "the first three words" has no fixed answer. Opening-words questions now ask for the opening as printed and are scored by letter prefix (`scoreAnswer(..., "prefix")`); table questions stay exact.
- The first full run showed models quoting the whole opening line, which the 24-letter prefix allowance rejected. The allowance is now 96 letters; the 120-character answer cap still rejects quoted paragraphs. The run was restarted at 11:42 on the final code and scorer.
- The fixture repeats one port table, so the 4 table questions do not discriminate between arms; the report says so.
