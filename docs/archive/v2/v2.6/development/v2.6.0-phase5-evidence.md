## The seam

`core/lifecycle/PreCompactHook.ts` subscribes to `lifecycle.context.preCompact`, writes a checkpoint, and swallows errors. It does not summarise or rewrite a thread. The summarise-and-commit path is `modules/coding/chat/ContextCompactor.ts` (`compact`, which now acquires `sharedCompactionLease` and delegates to `_compactHeld`). The user control calls `compactThread` in `core/chat/compactionSnapshot.ts`, which takes the same lease. The hook stays an observer.

The desktop renderer does not import the compactor. The sidecar methods are `chat.compact` and `chat.compact.undo`, both mapped to feature `f002`. Command parity after the addition: `PASS commands 145`.

## Accounting

`core/chat/contextAccounting.ts` is not a React module. `known + unaccounted === total` when the total is a number. A null category is the string `unknown`, not zero. Cache read and cache creation are separate fields and are not added into the total. The readout measures the next request (`observedTotal`), not a lifetime sum. Remaining is clamped at zero. The readout hides when the total is null, and on an empty thread at zero.

The Chat page passes that account into `ContextUsage` and shows `CompactControl` only while the account is visible. The first click names how many older turns will be summarised. The second click compacts. Undo restores the in-memory snapshot.

## What a restart does

Not durable yet. `DF-v260-2`: the open page updates, and undo works in that session. Reopening the app reloads the messages still stored in `chat_chat_messages`.
