# v2.6.0 Phase 2 evidence: conversation forking

**Plan**: `docs/v2/v2.6/plans/v2.6.0-adoption-chat-surface.md`
**Date**: 2026-09-26

## D2 outcome

A branch is a new session row. It stores `forked_from_session_id` and `forked_from_message_id`. The active leaf is `active_leaf_session_id` on the root row (and `active_leaf_chat_id` on the Chat pillar store). Maximum depth is 8. Cycles are rejected by an iterative walk. Delete is RESTRICT: a trigger aborts deletion of a session that still has branches, and deletion of a message that is still a branch point. `ON DELETE CASCADE` is not used for that relation.

## Migration precondition

`core/storage/preMigrationSnapshot.ts` exists and is already covered by `tests/unit/storage/preMigrationSnapshot.test.ts` from v2.5.0. This phase calls that helper. It does not add a second snapshot mechanism. v2.5.0 and v2.5.1 are tags on this history, and `origin/develop` contains the helper.

## Where the rows live

`src/storage/ChatHistoryStore.ts` is the store the plan names. Schema version is 3. A `user_version` above 3 throws `NewerSchemaError` before any stamp-down.

The Chat pillar's durable database is `modules/chat/storage/ChatExplorerStore.ts`. That file is the one whose old `currentVersion !== SCHEMA_VERSION` check stamped a newer database down. Schema version is now 4, the same downgrade refusal is in place, and the same branch columns and triggers are installed. A failed open closes the handle.
