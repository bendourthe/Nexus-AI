## D3, answered

- **A, schema**: keep all seven fields; CI enforces `evidence` paths and `name`-in-region only. `verificationCommand` and `testedAt` are advisory and never executed, because a checker that shells out to every command is a full test run wearing an inventory's clothes and would be too slow to gate a PR. The cost is stated rather than hidden: this gate cannot detect a feature that exists as a file and is broken.
- **B, region**: **both** regions, against the operator's choice of the broadest option. `## The Four Pillars` (10 `###` names) and `## Featured Capabilities` (19 table rows).
- **C, version**: removed entirely; consumers read `package.json`. The decisive argument is a failure mode rather than a preference: `semantic-release` bumps `package.json` on `main` without touching this file, so a gating version assertion would go red on the first release and be unfixable from inside the release commit that broke it. The checker now fails if a `version` field is reintroduced.

### Correction to the option I put to the operator

The choice was offered as "both regions, 30 names total". The real count is **29**: the pillars region has 10 `###` headings, not the 11 I estimated when writing the option. The decision is unaffected -- both regions are parsed -- but the number in the question was wrong and is corrected here rather than quietly matched to.

### The overlap is deliberate

Six capabilities appear in both regions under different wording (`Document parsing (OCR)` against `Document parsing`, `Ask inbox and scheduled runs (opt-in)` against `Ask inbox + scheduler`, and the two adapter pairs). They are separate entries sharing an `evidence` path, because they are two separate claims the README makes. Deduplicating would stop checking one of the two names.

## Verification

The checker was proven to fail before it was trusted, on four scenarios run against the real repository and then reverted:

1. **Broken evidence path** -> named the entry and the path.
2. **README names a feature the inventory lacks** -> named `"Quantum teleport"`.
3. **Malformed JSON** -> `not valid JSON`, failing closed rather than skipping.
4. **The false-pass case.** `GPU scheduler` was removed from the capabilities table while leaving it in changelog prose. The string appeared **3 times** in `README.md` and the checker still failed, because it reads only the two region slices. This is the specific defect the design exists to prevent.

Then 17 unit tests at `tests/unit/scripts/check-feature-drift.test.ts` -- `.test.ts`, confirmed collected by running it, not assumed -- covering those four plus a missing region heading, an empty region, a reintroduced `version`, duplicate ids, an unknown region, missing required fields, and a live assertion that the repository's own inventory agrees with its own README right now.

Full gate: 53 tests pass across the drift, docs and workflow-discipline suites; 21 workflows parse; docs-layout clean.

## Deviations

- The checker was refactored mid-phase to export a pure `analyze({inventoryRaw, readmeRaw, exists})` rather than reading files and calling `exit()` directly. The repo convention (`check-pr-checklist.test.ts`) imports pure functions from the `.mjs`, and a spawn-a-process test would have been slower and worse at asserting messages.
- Sub-task 3.4 was **not** cut, although the exit checklist permits it. The PR gate answers "did this change break it"; the daily job answers "is it broken right now", which is a different question once an administrator can bypass protection or a file is deleted out of band.
