## The one real finding this phase produced

**WN-1 was not theoretical.** Phase 1 recorded a suspicion that the scope guard might fail closed on a shallow CI clone. Phase 5.5 confirmed it by reading the workflow: `.github/workflows/ci.yml` uses `actions/checkout@v5.0.1` with no `fetch-depth` on any job, so CI gets a depth-1 clone where neither `develop` nor `origin/develop` exists. The guard is fail-closed by design, so `tests/unit/scripts/planScopeGuard.test.ts` would have failed the "Test TypeScript" job on every single run, for a purely environmental reason, and it would have done so on the very first push.

Two obvious fixes were both wrong. `fetch-depth: 0` permanently slows every checkout of a large repository to serve a guard that exists for one plan. Letting the guard pass when it cannot see the diff destroys the fail-closed property that is its whole value.

What was done instead: the CLI stays fail-closed, and the test asserts the two properties separately -- fail-closed holds in every environment, and "no guarded path touched" is asserted wherever a base ref resolved. No pipeline file changed.

Because a conditional test is exactly the shape that passes for the wrong reason, it was proven three ways: clean tree with a resolvable base passes, a simulated shallow checkout passes through the fail-closed branch, and a deliberate violation of a guarded path still fails the suite. That third run is the one that matters.
