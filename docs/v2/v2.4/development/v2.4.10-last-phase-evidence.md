**One real finding, found and fixed here (WN-1).**

`.github/workflows/ci.yml` uses `actions/checkout@v5.0.1` with **no `fetch-depth`** on any job:

```
$ grep -n -A 6 "actions/checkout" .github/workflows/ci.yml | grep -c fetch-depth
0
```

The default is a shallow clone (depth 1), so on CI neither `develop` nor `origin/develop` exists. The scope guard is fail-closed by design and returns `ok: false` when no base ref resolves, which would have failed the "Test TypeScript" job on every run for a purely environmental reason.

Two options were weighed. Setting `fetch-depth: 0` would fix it but slows every checkout of a large repository permanently, to serve a guard that exists for one plan. Weakening the guard to pass when it cannot see the diff would destroy the fail-closed property that is its entire value.

**Resolution taken**: neither. The CLI stays fail-closed (a developer running `node scripts/check-plan-scope-guard.mjs` locally still gets exit 1 and a `FAIL-CLOSED` message), and the test asserts the two properties separately: fail-closed holds in every environment, and "no guarded path touched" is asserted wherever a base ref resolved. **No pipeline file was changed.**

Proven three ways, because a conditional test is exactly the shape that can pass for the wrong reason:

