## What was found

The model does call tools, and does it well. With the vendor's own tool-definition block, it produced correct calls on 8 of 9 attempts (one seed refused on the file-read prompt), with stable output across seeds and correct multi-call sequencing.

What reaches Nexus is mutilated. Expected per `chat_template.jinja`:

```
<function name="get_weather"><param name="city">Paris</param></function>
```

Observed:

```
 name="get_weather"> name="city">Paris
```

Root cause, proven rather than inferred: `<function` (id 18), `</function>` (19), `<param` (20), and `</param>` (21) are all declared `special=True` in `tokenizer_config.json`, and Ollama's detokenizer omits special tokens from the `response` string.

The controlled experiment that isolates it: the model was asked to echo `<banana> <function <param </xyz>` and returned `'<banana>   </xyz>'`. The ordinary pseudo-tags survive; the two special ones vanish, leaving exactly the whitespace that separated them. Not prompting, not sampling, not a malformed model.

A top-level `"special": true` on `/api/generate` was tested against Ollama 0.32.15 and changed nothing, so there is no escape hatch at this version.

## Decision 2.2 and why option 2 was rejected

Option 2 looked textually available (stable format, no existing parser matches) and was rejected on substance:

- A parser for the **documented** grammar is dead code. It would pass fixtures written from the vendor grammar and return zero on every real transcript, producing a green suite that asserts a capability the product lacks.
- A parser for the **observed** stripped text is not a grammar parser. With no start tag, no end tag, and no call boundary, `get_weather`/`read_file` are separated only by a newline the grammar never promised, and a value ends only where the next ` name="` begins. Any parameter value containing ` name="` corrupts the parse. The plan's own 2.3 requirement, that a malformed call yield no span rather than a partial one, is unmeetable once the delimiters defining "malformed" are gone.
- It would breach the naming rule: every existing key names a grammar family shared across models; this would name one detokenizer's artifact in one runtime version.
- The hard stop condition is independently tripped. Both correct fixes (Ollama-side detokenization, or moving Nexus to `/api/chat` with structured `tool_calls`) lie outside `ToolCallFormat.ts`, the `ToolFormatName` union, and their tests.

`task: chat` was chosen over "no catalog row at all" because a `task: agentic` row would sort first among untagged Agentic rows (newest release date in the catalog), making the most prominent unticked agentic option the one known not to work, while `agentic: false` keeps it off that tab entirely. What remains is honest and useful for the same low-VRAM persona: Apache-2.0, 1.56 GB, 128K confirmed by local generate, CPU-capable, no revenue cap.

## Plan delta

**Disposition: False assumption -- non-blocking for this phase, blocking for Phase 4.**

The plan's Phase 2 was built to choose among three options, and it chose correctly and on evidence. Two assumptions underneath it were wrong, and neither could have been known before the probe.

**Evidence 1.** Sub-task 2.1 predicted `qwen-json` as the likely match, "which accepts the common `<tool_call>{json}</tool_call>` envelope". MiniCPM5 never emits that envelope; its grammar is nested `<function>`/`<param>` XML. Phase 1's session history already flagged this from the chat template, and the transcripts confirm it.

**Evidence 2, the one the plan could not have anticipated.** Every option in 2.2 assumes the wire format is *observable*. Option 1 asks which parser accepts it; option 2 asks for a parser named after it; even option 3 is framed as the model not "reliably emitting parseable tool calls". None of the three describes what actually happened: the model emits a perfectly parseable format, and the runtime removes the delimiters in transit. The blocker is neither the model nor Nexus but the boundary between them.

**Consequence for remaining phases.**

- Phase 3 runs in its reduced `task: chat` form: `agentic: false`, `toolCallingVerified: false`, no `toolCallingBenchmark`, `tags: []`, and card copy making no agentic claim. Its invariant hoist (3.2) and order assertions (3.3) still run in full and still carry their value.
- Phase 4 is **skipped in full**. `recommended.json` is not touched, so the cross-surface divergence the plan was written to correct is not exercised. That divergence remains real and stays recorded as a known gap for a future plan; this cycle simply produces no evidence about it.
- Phase 5's Goal-vs-codebase review must evaluate the conditional branch of the Definition of Done, not the primary one. The plan states this explicitly and Phase 5 will honor it.

No plan edit is required: the plan authored this branch itself and instructed exactly what to do in it. Recorded as a `DF` (DF-1) plus a supporting `NI-1` and `WN-2`.
