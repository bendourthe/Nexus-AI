## Plan delta

**Disposition: False assumption.** Non-blocking, but it changed what Phase 2 did.

**Observed evidence, item 1 (the load-bearing one).** The plan frames D2 as a decision that "changes branch protection, which is a repository-settings change", and its exit checklist asks whether "the CodeQL rename did not silently drop the old required check from branch protection". There was no branch protection:

```
$ gh api "repos/:owner/:repo/branches/develop/protection"   -> 404 Branch not protected
$ gh api "repos/:owner/:repo/branches/main/protection"      -> 404 Branch not protected
$ gh api "repos/:owner/:repo/rulesets"                      -> (empty)
```

A public repository with no protection and no rulesets. Nothing blocked a merge, so "gating" could only mean "the job turns its run red", and the branch-protection half of D2 had no subject. Surfaced to the operator, who chose to apply protection rather than record it, so 17 required checks now exist on `develop` and `main`.

**Observed evidence, item 2.** The plan states in bold that templating the CodeQL job name **"renames the existing TS check"**. It does not: the old value was the literal `Analyze (javascript-typescript)`, and `Analyze (${{ matrix.language }})` renders byte-identically for that matrix entry. Only a second check, `Analyze (python)`, is added. The warning was worth making and is wrong on this specific literal.

**Consequence for the remaining phases.**

1. **Phase 5.5 inherits a changed subject.** The terminal CI/CD reconciliation now compares against a repository that HAS protection, and the contract's "always-resolving aggregate required check" field is measurably unmet: 17 individual contexts, with three path-filtered workflows unrequirable without an aggregate. Filed as `QG-3` so 5.5 starts from the finding rather than rediscovering it.
2. **Phase 5.5's confirmation list gains two entries**, `gitleaks` and `pip-audit (model runtimes)`, which gate at the workflow level but are deliberately not yet required. Filed as `QG-2`.
3. **No phase scope changed.** The work Phase 2 was asked to do is the work it did.

Not escalated to a plan rewrite: the plan's instructions were right about what to build and wrong about the state of the repository it was building into, which is what a Plan delta is for.

## Deviations

The rename landed first, then was reverted on the reasoning that churning a check name branch protection references is the same footgun the plan flagged for CodeQL. The new job carries the disambiguation instead.

- **macOS is skipped on installer-smoke pull requests.** Not in the plan text. Its 10x multiplier is 75 percent of a full run's cost, and the workflow's own header documents an Actions budget freeze; full coverage stays on the monthly cron.
