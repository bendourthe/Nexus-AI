## Section 1: Executive answer

**Can Nexus AI Studio support this model? Text-only: probably, at meaningful cost. As described in the request (a vision model): no, and the blocker is Ollama, not Nexus.**

**Recommendation: do not adopt this artifact.** Adopt instead a narrower, cheaper item: a watchlist entry plus a one-page admission stub for *official* Qwen3.8-27B served from an official Ollama library tag, which would be a pure catalog row when it exists.

Three corrections to the request's framing, all material to the answer:

| Claim in the request | Actual | Why it matters |
| --- | --- | --- |
| "Qwen3 8B" | Qwen**3.8**-27B: a 27B dense model, not an 8B model. "3.8" is the Qwen release line, not the parameter count | Changes the hardware tier from laptop (8 GB) to 24 GB-class. This is the exact confusion trapdoor 7 of the v2.4.0 report warned against |
| "vision model" | The base line is vision-capable, but vision requires a separate `mmproj` projector file. Ollama does not support separate mmproj files | Nexus serves every LLM through Ollama. Vision through this path is unavailable, so the single most-cited feature would not work |
| "665K downloads" | Not confirmed. The model card surfaces 751 likes; a 665K download figure is not visible on the repository page | The popularity premise behind the request is unverified. It is also a community merge, not the official Qwen release |

## Section 4: Gap analysis

| # | Capability | Status in Nexus | Detail |
| --- | --- | --- | --- |
| A1 | Run a 27B dense `qwen35` GGUF | **Partially blocked** | Requires Ollama to support the `qwen35` architecture. Ollama has an open report of `unknown model architecture: 'qwen35moe'` on imported GGUF. Nexus cannot pin a runtime contract it does not control |
| A2 | Vision on this artifact | **Blocked upstream** | [Ollama does not support separate mmproj files](https://github.com/ollama/ollama/issues/9967). The documented workaround is merging projector and weights into one unified model with a Modelfile, which would make Nexus a model packager. Every vision LLM in the catalog instead relies on Ollama shipping a unified converted build under a library tag |
| A3 | MTP speculative decoding | **Missing, and out of reach** | MTP is driven by llama.cpp draft-model flags. Ollama exposes no equivalent. The headline speed feature is unavailable through the only serving path Nexus has |
| A4 | 256K context on a 24 GB card | **Partial** | Context window is a catalog field, but KV cache at 256K on a 27B model far exceeds the tier. Would need a truthful, measured `contextWindow` rather than the card's number |
| A5 | Uncensored LLM in the catalog | **Missing by precedent, not by accident** | Uncensored is established for image and video only. An uncensored LLM in an AI Work Assistant is a product decision, not a technical one |
| A6 | SHA-256 pinning for an `hf.co` Ollama pull | **Partial** | `ollama://hf.co/...` entries delegate digest verification to `ollama pull` and carry no sha256. Acceptable for pinned vendor repos; weaker for a community merge whose tags can move |
| A7 | Provenance for a multi-source merge | **Missing** | Catalog requires `provenance` on uncensored entries. This artifact's lineage is a stack of merges including abliterated components. Apache-2.0 is asserted on the merge; the chain through every parent is not established |

## Section 8: NOT recommended, with reasons

- **Q27-1, this DavidAU artifact in the catalog, installer, or Settings.** Fails admission gates 1 through 5. Vision, the headline reason for the request, does not work through Ollama's mmproj gap. MTP, the headline speed feature, is not reachable through Ollama. What would actually ship is a 17 GB text-only community merge with unverified merge-parent licensing and no tool-calling benchmark, competing against `qwen3-coder:30b` which already occupies the 24 GB tier with a pinned official tag.
- **Q27-2, a llama.cpp serving path.** Legitimate as a roadmap item and genuinely `re-full` under the policy, but adopting a second LLM runtime to accommodate one community merge inverts the cost/benefit. If a llama.cpp path is ever wanted, it should be driven by a runtime decision with its own comparison, not smuggled in as a model adoption.
- **Merging weights and mmproj into a unified Ollama model in-tree.** This makes Nexus a model packager, adds a redistribution surface with its own licensing exposure, and creates an artifact no upstream party maintains.

## Section 9: Trapdoors for the next cycle

1. Do not satisfy "add Qwen 3.8" with this artifact, with Flash-Next, or with any community merge. Official artifact plus official Ollama tag, or nothing.
2. "Vision model on Hugging Face" does not imply vision in Nexus. Check for an official Ollama library tag with a unified multimodal build. An `hf.co` GGUF pull is text-only.
3. A vendor-quoted download or like count is not evidence of fitness. This request cited 665K downloads against a page showing 751 likes.
4. Any uncensored LLM proposal is a product decision first. The existing uncensored entries are image and video only, and that boundary was deliberate.
