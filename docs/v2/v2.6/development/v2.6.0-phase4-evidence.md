## Capability diff

`desktop/src-tauri/capabilities/default.json` gained one permission:

```
"dialog:allow-open",
"dialog:allow-save"
```

There is no `tauri-plugin-fs` dependency and no `fs:allow-write-file`. The write is `export_diagram` in `desktop/src-tauri/src/export.rs`. It opens the save dialog itself. If the invoke payload includes a non-empty `path`, the command returns `renderer-supplied path rejected` and writes nothing.

## Command map

`scripts/check-command-parity.mjs` enumerates `IPC_METHODS` in the sidecar only. It does not read Rust macros. `export_diagram` is a Tauri command, not a sidecar method. Putting that name in `configs/command-capabilities.json` would fail the parity check as an unregistered command. The grant that authorises the dialog is `dialog:allow-save` in the capability file above.

## Export and versions

`sanitizeExportSvg` strips script, foreignObject, event handlers, and remote `url()` / `http` references. The SVG namespace `http://www.w3.org/2000/svg` is the one remaining http token, because it is the document namespace and is not fetched. Rasterising goes through a `draw` function that receives the sanitised string. The export tests spy on `fetch` and observe zero calls.

Retained versions: 20 per artifact thread. Pruning drops the oldest first and never drops the id currently being viewed. The viewer looks up by that id.

PNG is the first button on the diagram. SVG is the second.
