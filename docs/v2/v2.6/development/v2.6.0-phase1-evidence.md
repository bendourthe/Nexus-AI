## Why each feature stays

Each line is a cost the solo builder pays on this product today. None of them is "the comparison source had it".

**Forking.** The Chat pillar stores one linear transcript per chat. Trying a different next message means overwriting the only continuation or starting a new chat and pasting the prefix in by hand. After a restart, pasted copies have no record of the message they split from, and the builder cannot return to the continuation they were on. That cost is local and single-user. It does not depend on a hosted multi-tenant product. Depth is capped at 8, cycles are rejected, and delete does not cascade, so the feature cannot eat the history it is meant to protect.

**Mermaid rendering.** A model reply that contains a diagram fence is shown as source text. The builder cannot read the labels without leaving the app or trusting an external renderer. The artifact host only accepts a form payload. Rendering has to go through the existing sanitiser, with `style` still forbidden, because Mermaid's own CSS would otherwise force that list to shrink.

**Versioning and export.** A regenerated diagram replaces the previous picture in the transcript. The builder cannot step back to an earlier picture, and cannot save an inert PNG without a browser download that does not travel with the shell's content policy. Export is a save dialog plus one command that writes only the path that dialog returns. It is not a general filesystem grant.

**Context pressure and compaction.** The composer can show a single percent. It does not show which part of the window is unmeasured, and the only compaction path is automatic. The builder cannot see that an unknown slice was coerced away, and cannot undo a shortening they did not ask for. The readout and the compact control exist so a shortening is a choice on data the builder can still restore.
