## Plan delta

**Disposition**: False assumption (blocking).

**Evidence**: Stop-rule criterion (c) bounded the first call on the 60-page fixture at 5 minutes. The measured first call is 441 s, and almost all of it is RapidOCR's own throughput on this CPU (6.79 s per page), which `parse_document` already pays on the same pages today. The plan assumed this criterion would test the outline route; it tests the OCR engine.

**Consequence for remaining phases**: as written, the rule fires: Phases 3 to 5 are replaced by DF-v211-2 and the run continues at Phase 6. Whether to follow it or amend it is a maintainer decision, so the run is blocked (`approval-not-covered`) until that decision is recorded. Separately, the measurement shows the Phase 3 quality predicate needs space-insensitive heading matching for OCR text, and that the runtime's `pageCount` hides truncation past 200 pages.
