## Section 2: What changed since `18f56a79`

The prior report profiled VoiceStudio as a "local-first Tauri 2 desktop shell wrapping a Python model runtime" and called it "an unusually close structural analogue to Nexus-AI". **That premise has partly expired.** The README now opens with:

> NOTE: Electron Rewrite Ongoing: Please don't create desktop app related issues and pr

VoiceStudio is migrating its desktop shell from Tauri to Electron. The pyproject version is still 0.5.2, so none of this has been released; it all sits in the changelog's Unreleased section, headlined by "Electron now ships as a complete cross-platform VoiceStudio desktop app ... and the shared backend contracts required by those workflows (#1823)".

Concretely, the following did not exist at `18f56a79` and exists now:

| Area | Evidence | Note |
|---|---|---|
| A complete second desktop shell | `electron/` with `src/`, `tests/`, `electron-builder.config.mjs`, `electron.vite.config.ts`, `CONTRACT.md`, `PARITY.md` | Both shells coexist during migration |
| A machine-checked parity ledger | `electron/PARITY.md` plus `tests/test_electron_parity_inventory.py` | See V1 |
| A packaged-app smoke suite | 67 files matching `electron/tests/*smoke*.mjs`, wired into `.github/workflows/ci.yml:195-216` | See V2 |
| A signed updater with channels | `electron/src/main/updater.ts` (+ `updater.test.ts`), `electron/src/renderer/src/features/settings/update-settings.tsx` | See V3 |
| A packaged accessibility smoke | `electron/tests/accessibility-smoke.mjs` | See V4 |
| Release-asset verification | `scripts/check_electron_release_assets.py` | See V5 |
| Per-engine one-click environments | Changelog #2021, #2022, #2025: VoxCPM2, MOSS-TTS-Nano and CosyVoice 3 each install into their own environment with a pinned dependency set | See Section 5, not recommended |
| Model Catalogue consolidation | Changelog #2013, #2020: one page, one line per engine, weights installed from the engine's own panel | Design-only; noted, not adopted |

The Electron migration itself is **not** an adoption candidate (Section 5). What is valuable is the **discipline VoiceStudio built to survive the migration**, because Nexus-AI has a migration of its own already planned: `docs/v2/v2.5/plans/v2.5.0-migration-durability.md`.

## Section 3: Delta findings against Nexus-AI

Each finding was verified against this tree rather than assumed.

### V1. Machine-checked shell parity ledger

`electron/PARITY.md` is a capability inventory, one row per user-visible area, mapping the Tauri source file to an explicit Electron status. Its design contract opens with the sentence that makes it useful rather than decorative:

> A route or a screenshot alone does not count as parity.

The enforcement sits in `tests/test_electron_parity_inventory.py`, whose comment states the rule directly:

> Every registered native command must be assigned to a user-visible parity area. A new Tauri command therefore cannot land without an explicit Electron parity decision.

**Nexus-AI state**: `docs/v2/v2.5/plans/v2.5.0-migration-durability.md` exists as a plan, with no equivalent mechanical enforcement. Nexus-AI's own `feature_list.json` plus drift checker (adopted as A3 in v2.4.9) is the closest structure and is the natural place to extend, not a second parallel mechanism.

**This is the highest-value item in the delta**, because it is the one that arrives exactly when Nexus-AI needs it.

### V2. Packaged-app smoke suite replacing a manual checklist

VoiceStudio runs 67 `*-smoke.mjs` scripts against the packaged renderer, invoked from CI (`.github/workflows/ci.yml:192-216`, including a "Production-bundle smoke - no blank screen" step and named renderer workflow smokes).

**Nexus-AI state**: packaged verification is **manual**. `docs/v2/v2.4/development/v2.4.1-operator-checklist.md` is a human checklist, and its evidence is hand-captured media (`docs/v2/v2.4/development/artifacts/installed-media-smoke.{mp4,png}`, `installed-media-smoke-report.json`). The v2.4.1 changelog states the position plainly: "packaged-smoke evidence is local-first; the operator checklist keeps clean/repair install visuals, live CUDA generation, and packaged interaction checks explicit until observed."

That is a defensible position for GPU-dependent and visual checks. It is not defensible for the deterministic subset: does the packaged bundle mount, do the four pillar routes load, does settings open, does the sidecar handshake complete. Those are exactly the checks a blank-screen regression would fail, and they are the ones VoiceStudio automated first.

### V3. Signed updater with Stable and Preview channels (deferred item A11)

`electron/src/main/updater.ts` defines two feeds keyed by channel, resolves a per-platform and per-arch manifest name (`feedManifestName`), and implements explicit version comparison (`compareReleaseVersions`) including a fourth pre-release component. `update-settings.tsx` exposes the channel choice to the user. `scripts/check_electron_release_assets.py` verifies the release actually published the assets each channel expects.

**Nexus-AI state**: **no updater exists at all.** Grepping `updater` and `createUpdaterArtifacts` in `desktop/src-tauri/tauri.conf.json` returns nothing. A11 remains entirely unimplemented, and now has a working reference design for the manifest-per-channel-per-platform layout and the release-asset check that prevents publishing a channel with missing artifacts.

**Important**: the reference implementation points at GitHub's releases API and download endpoints. For Nexus-AI this is a genuine outbound call in a product that makes zero by default, which constrains how it may be adopted (Section 5).

### V4. Packaged accessibility smoke

`electron/tests/accessibility-smoke.mjs` runs an accessibility check against the packaged app.

**Nexus-AI state**: no accessibility tooling of any kind. Grepping `jsx-a11y`, `axe-core`, `@axe-core` and `vitest-axe` across `package.json`, `desktop/package.json`, `eslint.config.mjs` and `desktop/eslint.config.mjs` returns zero matches.

This independently confirms the top finding of the LibreChat comparison authored alongside this one ([`v2.5.1-comparison-librechat.md`](v2.5.1-comparison-librechat.md), item LC-2). Two unrelated peers, one a web chat client and one a desktop voice studio, both gate on accessibility while Nexus-AI has nothing. **Treat the a11y item as one shared adoption, not two**: LC-2 covers the lint and component-level smoke, V4 extends the same `axe-core` dependency to the packaged shell once V2 exists to host it.

### V5. Release-asset verification

`scripts/check_electron_release_assets.py` asserts the expected artifact exists for each channel, platform and arch before a release is considered publishable.

**Nexus-AI state**: four installer workflows exist (`installer-build`, `installer-linux`, `installer-macos`, `installer-smoke`) plus `release.yml` and `semantic-release.yml`, but no single check asserts that a finished release carries the complete expected artifact matrix. Given that `semantic-release` publishes from `main` automatically, a missing artifact is discovered by a user rather than by CI.

## Section 5: Security and Reverse-Engineering Assessment (MANDATORY)

### 5.1 Threat model comparison (delta only)

The prior report's threat model is unchanged for everything except V3. The Electron migration adds no new outbound destination to VoiceStudio's runtime that matters here, with one exception:

| Dimension | Nexus-AI (today) | VoiceStudio (new) | Delta if V3 adopted naively |
|---|---|---|---|
| Outbound destinations at runtime | None by default | GitHub releases API plus per-channel download endpoints, on update check | **An outbound call on app start** in a product whose central claim is that none occur |
| Credentials required | None | Code-signing key custody for the publisher | Signing-key custody, a new operational secret |
| New commercial relationship | None | None (GitHub already hosts the repo) | None |
| User content leaving the machine | No | No (update check sends a version, not content) | None, provided the check carries no telemetry payload |

The update check is the only genuinely new trust decision in this delta, and it is a real one: an auto-updater is a remote-code-delivery channel into a local-first app.

## Section 7: Risks and Conflicts

**R1 -- License conflict (critical, carried forward unchanged).** VoiceStudio is **AGPL-3.0-only**; Nexus-AI is **MIT**. Copying VoiceStudio source into Nexus-AI would impose AGPL obligations on a codebase that does not carry them. Every item in Section 6 must be implemented **clean-room from the described behavior**, not by copying files, functions, test scripts or workflow YAML from the clone. This applies with more force in this delta than in the prior report, because V1, V2 and V5 all have a concrete, tempting reference file in the clone. The scratchpad clone must be deleted after this comparison.

**R2 -- V1 risks becoming a second inventory.** Nexus-AI already has `feature_list.json` and its checker from A3. Building a separate parity ledger alongside it produces two inventories that drift against each other, which is worse than one. V1 must **extend** the existing checker, not sit beside it.

**R3 -- V2 can regress into flake.** A packaged-app smoke that drives real UI is the classic source of nondeterministic CI. Restrict the first cut to assertions that are deterministic (does the bundle mount, does a route render, does the handshake complete) and keep anything timing-dependent or GPU-dependent on the manual checklist where it already lives. A flaky packaged smoke that gets disabled is worse than an honest manual checklist.

**R4 -- V3 changes the product's privacy posture.** An updater that phones home on start contradicts "no data leaving your machine" unless it is opt-in and says so. Default off, explicit consent, no telemetry payload beyond the version string, and documented in `SECURITY.md`. If that is unacceptable, the fallback is a check-on-demand button rather than an automatic check.

**R5 -- V3 is a remote-code-delivery channel.** Signing-key custody is the whole security model. A compromised or careless key turns the updater into the most effective possible attack on every installed copy. This is the reason A11 was deferred once already, and none of it is solved by VoiceStudio having shipped an implementation.

**R6 -- The structural-analogue premise has weakened.** The prior report leaned on VoiceStudio being a Tauri peer. It is becoming an Electron app. Future VoiceStudio comparisons should not assume shell-level transferability; the backend, packaging and field-discipline layers remain comparable, the shell layer increasingly does not.
